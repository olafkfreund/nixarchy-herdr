# Intent: a readable, discoverable, adjustable panel and menu

Closes #23. This is the last of four issues from the 2026-11-16 review. #20
(robustness), #21 (upstream sync) and #22 (herdr-core and herdr-app agents),
plus PR #27, are merged and live on p620 with plugin 1.1.0. On 2026-11-17 the
owner added one outcome to this issue: changing the text size from the
keyboard.

## Problem

The plugin works, but it is harder to read and learn than it needs to be.
Checked on master `7b678da`:

- **Text size is fixed.**
  - There is no way to make the panel or the menu text bigger or smaller.
    Every size in `Card.qml` and `Menu.qml` is multiplied by a `textScale`,
    but `Menu.qml:64` fixes it at 1.0 and `Panel.qml` never sets one.
  - The only lever is the theme's font size, which changes the whole
    desktop.
- **Light themes flatten the hierarchy.**
  - Secondary text is dimmed with `Qt.darker` (14 uses, mostly in
    `Card.qml`).
  - On a dark theme that makes text fainter. On a light theme it makes
    already-dark text darker, so the primary and secondary lines look the
    same.
- **The badge number changes meaning.** `Panel.qml:254` shows the blocked
  count when anything is blocked, otherwise the number of running servers,
  otherwise a `!` while herdr-core is stale. The same `3` can mean "3 agents
  need you" or "3 servers are up".
- **Hidden keys.**
  - `n`, `a`, `i`, `K` and `x` are documented only in the README and in
    `herdr-menu-keys`. Nothing in the panel hints at them, and an empty list
    doesn't say how to start.
  - Killing and deleting are two keys, though a row only ever allows one of
    them.
- **The cursor can leave the screen.**
  - Keyboard scrolling keeps the cursor's *session* in view (`Card.qml:67`).
  - On a tall session, the highlighted agent can be off-screen.
- **A column cursor that adds little.**
  - Right and Tab move onto the row's buttons, which sit on the session line
    even while the cursor is on an agent.
  - Letter keys already do the same things.
- **The `n` input is unforgiving.** It has no placeholder, and it defaults to
  whichever host the cursor is on, which can be razer.
- **The prompt reply is rebuilt, not shown.**
  - `replyFrom()` (`Menu.qml:293`) reconstructs the agent's reply from the
    screen and mangles code.
  - The wait shows neither the elapsed time nor that Esc cancels.
- **Layer and motion.**
  - The pinned card and the menu sit on `WlrLayer.Overlay`
    (`Panel.qml:323`, `Menu.qml:354`), above fullscreen windows.
  - The attention blink never stops.
  - Pinning from the keyboard leaves the card without focus.
- **Accessibility.**
  - Rows have names, but focus isn't exposed (`Accessible.focused`).
  - The input and the icon buttons have no names.
- **Duplicated work.**
  - Every monitor's bar button and the menu each run their own model, so
    each one polls herdr and holds its own `hc events` subscription.
- **Dead code.**
  - the `dropped` counter;
  - unused JSON totals and imports;
  - a confirm overlay written twice (`Menu.qml` and `Card.qml`);
  - the blocked > done > working order written about seven times.
- **The README has drifted.** It describes some text styling and badge
  behaviour that the code doesn't do.

## Proposed outcome

- **Text size from the keyboard.**
  - In the panel and the menu, `+` (or `=`) makes text bigger, `-` makes it
    smaller, and `0` resets it. Ctrl with the same keys works too.
  - The steps are fixed, with a sensible minimum and maximum. Rows and the
    card widen with the text instead of clipping it.
  - The size is remembered across shell restarts.
- **Readable on light and dark themes.** Secondary text is visibly fainter
  than primary text on both.
- **The badge number has one meaning.** The tooltip carries the breakdown
  (blocked, done, working, servers, stale).
- **Keys you can find.**
  - A one-line key hint at the bottom of the panel and menu.
  - `?` opens the key sheet.
  - An empty list says how to start a session.
  - One destroy key kills or deletes, whichever the row allows.
- **The cursor stays visible.** Scrolling keeps the highlighted agent on
  screen.
- **A friendlier `n`.**
  - A placeholder in the input.
  - It stays open until the session starts.
  - It keeps the text on error.
  - It defaults to this machine.
- **The prompt reply is the agent's own text.**
  - A bounded raw excerpt replaces `replyFrom()`.
  - The wait shows the elapsed time and "Esc cancels".
- **Layer and motion.**
  - The pinned card and the menu stay below fullscreen windows.
  - The blink stops after a while.
  - Pinning keeps keyboard focus.
- **Accessible.** Focus is exposed to assistive technology, and every input
  and icon button has a name.
- **One data model per shell, not per surface.** The badge, the panel and
  the menu show the same counts at the same moment.
- **The dead code is gone, and the README matches the code.**
- **Nothing that works today breaks.** Classic sessions, app agents,
  remotes, kill and prompt keep their #20 and #22 behaviour and tests.

## Affected users and systems

- **Users:** everyone using the bar button, the pinned card or the menu, on
  any theme, with or without assistive technology.
- **Files:**
  - `Card.qml`, `Panel.qml`, `Menu.qml` and `HerdrModel.qml`;
  - possibly a new shared-model file;
  - `bin/herdr-menu-keys`;
  - `README.md`;
  - the tests.
- **Hosts:** p620 and razer, through a nixarchy pin bump and a deploy.
- **The deploy needs a shell restart.** After the #22 deploy,
  `omarchy-shell shell reloadPlugins` kept the old `HerdrModel` type. Only
  `omarchy-restart-shell` loaded the new code.

## Constraints

- **No behaviour from #20 or #22 regresses.** That covers:
  - deadlines;
  - identity-based cursor;
  - captured targets;
  - not-live refusals;
  - the cascade-checked kill.

  The existing tests stay green.
- **No live testing on p620's desktop beyond read-only checks and throwaway
  sessions.** The owner asked that nothing breaks. Visual checks use demo
  mode or a microVM where possible.
- **Sizes follow the theme.** Text and spacing stay `Style.font` and
  `Style.space` based; the text size only multiplies them. The earlier
  screen-height scaling stays out (`Menu.qml:58-63`).
- **Keys must not clash.**
  - The new keys can't take a letter the card already uses (`o K p r n a i`,
    Enter, Esc and the arrows).
  - They must not swallow typing in the `n` or prompt inputs.
- **The saved text size is the only new state written to disk.** It goes in
  the plugin's existing cache directory.
- **Implementation:** the owner asked for multi-agent workflows to implement
  this. That starts only after the plan is approved.

## Open questions

1. **What the badge number means.** Recommendation: the number of agents that
   need you (blocked, plus done-not-seen). With none, no number: just the
   icon, plus `!` while stale. Servers move to the tooltip.
2. **The text-size range.** Recommendation: 0.8x to 1.6x in 0.1 steps. One
   size shared by the panel, the pinned card and the menu.
3. **Drop the column cursor entirely?**
   - Recommendation: yes. Buttons stay clickable with the mouse, and every
     button has a letter key.
   - This removes Right/Tab navigation, which someone may use.
4. **One shared model: in this issue, or a follow-up?** It is the largest
   change here and touches every surface. Recommendation: keep it in, as its
   own plan step, so the counts agree everywhere.
5. **Which layer to use instead of Overlay.** Recommendation: Top for the
   pinned card and the menu, checked against a fullscreen window.
