# Intent: a readable, discoverable, adjustable panel and menu

Closes #23, the last of four issues from the 2026-11-16 review.
- #20 (robustness), #21 (upstream sync) and #22 (herdr-core and herdr-app
  agents), plus PR #27, are merged.
- p620 runs plugin 1.1.0.
- On 2026-11-17 the owner added one outcome: changing the text size from the
  keyboard.

Revision 2, after reviews by Codex (gpt-6.1-sol) and agy (model not reported).
It corrects counts and claims, and adds the hidden-badge bug. It drops
dead-code items that don't exist, and moves design choices into open
questions.

## Problem

Checked on master `7b678da`.

- **An agent waiting on you can have no badge at all (bug).**
  - The badge shows only if a classic herdr server is running, unless
    herdr-core is stale: `badgeShown` (`HerdrModel.qml:139`) needs
    `runningCount > 0`.
  - App spaces don't count as servers (`HerdrModel.qml:327`).
  - On a machine with only `hc`, which the README supports (`README.md:151`),
    a blocked or finished-unseen app agent shows nothing in the bar.
- **The badge number changes meaning.** The text is the blocked count, else
  the number of running servers, else `!` while herdr-core is stale, else
  nothing (`Panel.qml:254`).
  - The same `3` can mean "3 agents need you" or "3 servers are up".
  - Stale makes the colour urgent but doesn't replace a number
    (`HerdrModel.qml:943`).
- **Text size is fixed.**
  - Text and icon sizes multiply a `textScale`.
    - `Menu.qml:64` fixes it at 1.0.
    - `Panel.qml` sets none, so `HerdrModel.qml:22` falls back to 1.0.
  - The confirm dialogs don't use it.
  - Spacing and card widths don't scale. The widths are fixed or capped
    (`Panel.qml:103-105`, `:366-370`, `Menu.qml:65`, `:376`), while long text
    elides.
  - The only lever today is the theme's font size, which changes the whole
    desktop.
- **Light themes flatten the hierarchy.**
  - Secondary text is dimmed with `Qt.darker` (17 calls: 11 in `Card.qml`,
    2 in `Menu.qml`, 1 in `Panel.qml`, 3 in `HerdrModel.qml`; some colour
    icons and grips).
  - On a light theme that darkens already-dark text, so the primary and
    secondary lines look alike.
- **Keys are hard to discover.**
  - Only the pin button's tooltip names a key (`p`, `Card.qml:195`).
  - `n`, `a`, `i`, `K`, `x`, `r` and `o` are listed only in the README and in
    `herdr-menu-keys`.
  - The empty list says "No herdr sessions" (`Card.qml:676`), not how to
    start one.
  - Killing and deleting are two keys, though a row only ever allows one of
    them.
- **The highlighted agent can scroll off screen.** Scrolling keeps the
  cursor's *session* in view (`Card.qml:67`, `HerdrModel.qml:683-688`), so in
  a tall session the highlighted agent can sit below the fold.
- **The column cursor duplicates the letter keys.**
  - Left/Right, h/l and Tab/Shift+Tab move onto the row's buttons
    (`bin/herdr-menu-keys:23-25`).
  - Those buttons sit on the session line even while the cursor is on an
    agent.
  - `o`, `K` and `x` already do what they do.
- **`n` hides two choices.** The input has no placeholder (`Menu.qml:455`).
  Where the session is made, and whether it's a classic session or an app
  space, both come silently from the row under the cursor
  (`Menu.qml:141-143`, `:173`), which can be razer.
- **The prompt reply is rebuilt, not shown.**
  - `replyFrom()` (`Menu.qml:293-318`) strips indentation and blank lines and
    joins lines, which mangles code.
  - The wait shows neither the elapsed time nor that Esc cancels
    (`Menu.qml:236`).
- **Layer and motion.**
  - The pinned card and the menu sit on `WlrLayer.Overlay` (`Panel.qml:323`,
    `Menu.qml:354`), above fullscreen windows.
  - The attention blink (`Card.qml:487`) has no time limit. It runs for as
    long as an agent wants attention.
  - Pinning from the keyboard has no explicit focus hand-over
    (`Panel.qml:136-139`).
- **Accessibility gaps.**
  - Rows have names (`Card.qml:250`, `:402`), but nothing sets
    `Accessible.focused`.
  - The input and the icon buttons have no explicit names.
- **Redundant collection.** Each bar button (one per monitor) and the menu
  run their own model, and each holds its own `hc events` subscription
  (`Panel.qml:56`, `Menu.qml:91`).
  - Their scope differs on purpose: the bar is this machine, while the menu
    adds remotes.
  - So differing counts are not a bug. The repeated work for the same local
    data is.
- **Maintenance.**
  - The blocked > done > working priority is decided separately in
    `attentionRank`, `noteLabel`, `noteColor`, `statusColor` and `badgeColor`
    (`HerdrModel.qml:615`, `:855`, `:928`, `:935`, `:943`).
  - The two confirm overlays (destroy in `Card.qml:695`, busy-send in
    `Menu.qml:498`) repeat the same input-blocking scaffolding.
  - `Panel.qml:2` and `:5` look like unused imports.
- **The README has drifted.**
  - It promises bold, coloured agent titles (`README.md:203`); the code draws
    plain, darkened ones (`Card.qml:528-549`).
  - Its polling description (`README.md:284-286`) differs from
    `HerdrModel.qml:1239-1241`.

## Proposed outcome

- **An agent that needs you always shows on the badge,** on any machine:
  classic only, `hc` only, or both.
- **The badge number has one meaning.** The tooltip gives the breakdown:
  blocked, done, working, servers, stale. A stale herdr-core stays visible
  even when there is a number.
- **Text size from the keyboard (owner request).**
  - Keys make the panel, the pinned card and the menu text bigger or smaller,
    and reset it.
  - The size moves in fixed steps between a minimum and a maximum.
  - Rows and the card widen up to the screen's room. Beyond that, long text
    elides rather than overlapping.
  - The size survives a shell restart.
  - Typing in the `n` and prompt inputs is never taken over: `task-0`,
    `/tmp/c++` and `x=0` type as written.
- **Readable on light and dark themes.** Secondary text is visibly fainter
  than primary text on both, and still meets readable contrast.
- **Keys you can find.**
  - Visible key hints in the panel and the menu.
  - A key that opens the key sheet.
  - An empty list says how to start.
  - One destroy key does whichever of kill or delete the row allows.
- **The highlighted agent stays on screen** while moving with the keys.
- **`n` says what it will make, and where, before you type.** It has a
  placeholder. It never silently makes something on a remote host, and making
  one on a remote host stays possible on purpose.
- **The prompt reply is the agent's own text,** with its line breaks and
  indentation. It is capped at a stated length, and the wait shows the
  elapsed time and how to cancel.
- **Layer and motion.**
  - The pinned card and the menu don't cover fullscreen windows, yet still
    open and close from the keyboard.
  - The blink stops after a stated time.
  - Pinning keeps keyboard focus.
- **Accessible.** Focus is exposed, and every input and icon button has a
  name.
- **One priority rule and one confirm scaffold,** used everywhere. The
  unused imports are gone.
- **The README matches the code.**
- **Nothing that works today breaks.** These keep their behaviour and tests:
  - classic sessions, app agents and remotes;
  - kill (with its cascade check) and prompt (with its busy confirmation);
  - the `n` input staying open until success, keeping text on error, and
    going read-only while pending (`Menu.qml:167-188`, `:463`), which
    already works;
  - #20's deadlines and identity-based cursor;
  - #22's not-live refusals.

## Affected users and systems

- **Users:** everyone using the bar button, the pinned card or the menu, on
  any theme, with or without assistive technology. Users on `hc`-only
  machines get a working badge.
- **Files:**
  - `Card.qml`, `Panel.qml`, `Menu.qml` and `HerdrModel.qml`;
  - `bin/herdr-menu-keys`;
  - `README.md`;
  - the tests.
- **Hosts:** p620 and razer, through a nixarchy pin bump and deploy.
- **The deploy needs a shell restart.** After #22, `reloadPlugins` kept the
  old `HerdrModel` type, so only `omarchy-restart-shell` loads new plugin
  code.

## Constraints

- **The regression list above stays green.**
- **Live checks on p620's desktop are read-only or use throwaway sessions.**
  The owner asked that nothing breaks. Visual checks use demo mode or a
  microVM where possible.
- **Sizes stay theme-based.** Text and spacing remain `Style.font` and
  `Style.space` based; the text size only multiplies them. The old
  screen-height scaling stays out (`Menu.qml:58-63`).
- **The new keys don't clash.**
  - They take no letter the card uses: `o K p r n a i x`, Enter, Esc, the
    arrows, and h/j/k/l while the column cursor exists.
  - Bare characters stay literal in both inputs.
  - Shifted characters such as `+` are matched without catching unrelated
    modified keys.
- **The saved text size is the only new state written to disk,** in the
  plugin's existing cache directory.
- **Implementation:** the owner asked for multi-agent workflows to implement
  this. That starts only after the plan is approved.

## Open questions

1. **The badge number.**
   - Recommendation: agents that need you, meaning blocked plus done and not
     yet seen.
   - With none, show no number, just the icon (servers move to the tooltip).
   - `!` while stale is shown alongside a number, not instead of it.
2. **Text size.**
   - Recommendation: `+` (or `=`), `-` and `0`, with or without Ctrl, outside
     the inputs; inside them, only the Ctrl chords.
   - 0.8x to 1.6x in 0.1 steps, one size shared by every surface.
3. **The column cursor.** Recommendation: drop it (Left/Right, h/l,
   Tab/Shift+Tab), since every button keeps a letter key and stays clickable.
   The README and the key sheet say so.
4. **`n` and remote hosts.**
   - Recommendation: `n` makes a classic session on this machine.
   - On a row that is an app space or a remote host, the input's label says
     so ("new space on razer") and that row's choice is used. So the remote
     route stays, but always labelled.
5. **One shared model.**
   - Recommendation: a follow-up issue, not this one. The model also holds
     each surface's cursor, focus and confirm state (`HerdrModel.qml:15-23`,
     `:123-125`), and the bar (local) and the menu (remotes) differ in scope.
   - Codex recommended the follow-up; agy recommended sharing now.
6. **The layer.**
   - Recommendation: Top, if a check against a fullscreen window shows the
     keyboard still opens and closes the menu.
   - The menu asks for exclusive keyboard focus (`Menu.qml:355`), so that
     check matters.
