# Intent: actions never hang, the cursor stays on what you picked, failures say why

Closes #20. This is the first of four issues from the 2026-11-16 review (Codex,
agy, Fable, all checked against the code). The others: #21 upstream sync, #22
herdr-core/herdr-app, #23 UI pass. This one goes first so #22 builds on the
fixed timeouts and cursor identity.

## Problem

The plugin's defensive input checks hold up: no injection path was found. Its
failure handling doesn't. Some failures freeze it; others look like success, or
like an empty session.

**It freezes**
- **One stuck call blocks every action, kill included.** `HerdrModel.qml:251`
  drops any action while another is running. Local `herdr agent focus`
  (`bin/herdr-sessions:658`), `socket_of` (`:850`) and `herdr session delete`
  (`:903`) have no timeout. So clicking an agent on a wedged server makes `K`
  dead until the shell restarts, which is the exact case kill exists for. A
  remote `new` holds the same lock for up to 20 × 8.5 s.
- **Refresh time grows with the number of wedged servers.** Snapshots run one
  after another, 2 s each (`:393-411`). A few slow servers on a remote host
  push the whole host past ssh's 8 s limit, and it shows as down.

**It acts on the wrong thing**
- **The cursor is a row number, and the rows re-sort by agent state on every
  poll.** `rebuild()` only clamps the number (`HerdrModel.qml:217`). Enter or
  `a` can reach a different agent from the one highlighted, and `column` is not
  re-clamped.
- **Kill finds its target loosely.** The socket is matched by substring, the
  first `pid=` on the `ss` line is taken, and the PID is not re-checked before
  SIGKILL (`:830-886`). `window_map` treats any herdr process that isn't
  `server` (`herdr agent prompt`, `--session=foo`, `-s foo`) as a window of the
  default session (`:286-311`).

**It hides failures**
- **Errors are dropped.** Open, focus and new close the surface before their
  result arrives (`HerdrModel.qml:272`, `Menu.qml:145`). An invalid name returns
  without a word (`:583`). Output that isn't JSON clears `actionError` (`:879`),
  and reopening the menu clears it again (`:798`). Focus failures are `|| true`.
- **One bad snapshot blanks every session.** The merged object is validated as a
  whole and replaced by `{}` (`bin/herdr-sessions:442`). A timed-out snapshot
  reads as "0 agents" with `ok:true`. Untitled agents count towards the badge
  but get no row (`:484`), so the badge can read "needs you" with nothing to
  click.
- **Stale data looks current.** Remote rows from the last open are redrawn on
  reopen, and a host reads "down" before its first answer (`HerdrModel.qml:224`).
  Edits to `herdr.json` leave removed hosts on screen. A failed local poll keeps
  old counts in the tooltip (`:787`).

**Smaller**
- Demo mode still lists real remote sessions (`bin/herdr-sessions:932`).
- The prompt text sits in herdr's argv (`:778`, `:785`), although the comment
  says it never does. `herdr agent prompt` has no stdin form. The reply screen
  goes through `jq --arg` and can exceed the per-argument limit (`:820`).
- `cleanTitle()` strips leading CJK, Cyrillic and Greek text ("修复 API" becomes
  "API"). The attention tie-break contradicts its own comment
  (`HerdrModel.qml:638`, `:751`). Both were reproduced.
- One unseen "done" agent keeps every monitor polling at 5 s for good
  (`HerdrModel.qml:92`).

## Proposed outcome

- **No action waits longer than a bounded time,** locally or over ssh. When the
  time runs out, the menu names the action. Kill still works after a focus on a
  wedged server.
- **Actions don't vanish.** A second action while one is running is either
  queued or refused with a message, never dropped silently.
- **The cursor follows the agent or session you put it on** (host, session,
  pane) across refreshes. It moves only when that item disappears.
- **Every failure is shown.** A bad name, an existing session, a missing
  directory, a host that didn't answer, an unreadable server: each gets a line.
  The `n` input stays open with your text until creation succeeds.
- **A server that can't be read is shown as unreadable, not as empty.** The
  other sessions are unaffected, and every agent the badge counts has a row.
- **One slow server doesn't delay the others,** and a slow host isn't reported
  down because of one server.
- **Data from the last time is marked as checking** until the host answers.
  Removed hosts disappear when `herdr.json` changes.
- **Kill signals only the herdr server that owns that exact socket,** and
  re-checks the PID before each signal.
- **Demo mode shows nothing real,** remote rows included.
- **The README and comments match the code** on where prompt text goes.
- **Each fixed behaviour has a test** in `tests/herdr-sessions.sh` or
  `tests/session-actions.cjs`.

## Affected users and systems

- **Users:** everyone using the menu or the bar panel, most of all with
  several sessions or remote hosts.
- **Files:** `HerdrModel.qml`, `Menu.qml`, `bin/herdr-sessions`, both test
  files, and `README.md` (the prompt privacy sentence). `Card.qml`/`Panel.qml`
  only if the cursor identity needs them.
- **Hosts:** p620 and razer (razer is the remote host), through the usual
  nixarchy pin bump.

## Constraints

- **No new behaviour or UI beyond what's listed here.** The visual changes are
  #23, herdr-core is #22.
- **Keep the existing defences:** shape checks on both ends, byte caps, `--`
  and `%q` for ssh, `BatchMode=yes`, PlainText. The script still runs over ssh
  piped on stdin, with nothing installed on remote hosts (decided 2026-11-16).
- **Remote hosts keep `herdr.json` + ssh** (decided 2026-11-16), not
  `herdr --machine`.
- **Tests run against fakes only.** No test may touch a real herdr server.
- **Merge with a merge commit.**

## Open questions

1. **A second action while one is running:** queue it (runs after) or refuse
   it with a "busy" line? Recommendation: refuse, except kill, which always
   runs, in its own process.
2. **Prompt text in argv:** accept it and correct the README and comment, or
   drop the prompt feature when herdr can't take stdin? Recommendation: correct
   the claim. herdr's own CLI is the limit, and #22 sends hc prompts through
   `hc send`.
3. **Snapshot concurrency:** collect snapshots in parallel (bounded, say 4 at a
   time), or keep them sequential under one deadline for the whole refresh?
   Recommendation: bounded parallel plus a whole-refresh deadline.
