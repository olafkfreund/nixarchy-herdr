# Intent: actions never hang, the cursor stays on what you picked, failures say why

Closes #20. This is the first of four issues from the 2026-11-16 review (Codex,
agy, Fable, all checked against the code). The others: #21 upstream sync, #22
herdr-core/herdr-app, #23 UI pass. This one goes first so #22 builds on the
fixed timeouts and cursor identity.

## Problem

Session, pane and host names are shape-checked on both ends, and no injection
path was found. Failure handling is the weak side: some failures freeze the
plugin, others look like success, or like an empty session.

**It freezes**
- **One stuck call blocks the next session actions through that model, kill
  included,** until the process exits. `HerdrModel.qml:251` drops any action
  while one is running. Local `herdr agent focus` (`bin/herdr-sessions:658`),
  `socket_of` (`:850`) and `herdr session delete` (`:903`) have no timeout, so
  after you click an agent on a wedged server, `K` on that server does nothing.
  Kill exists for exactly that case. A remote `new` with a directory holds the
  same lock for up to about 186 s (`:674`, `:709-716`, `:718`).
- **A prompt can hang after its timeout.** Once `agent prompt` returns or times
  out, the local `agent get` and `agent read` calls have no deadline and no
  signal trap (`:790-806`). The input line stays read-only (`Menu.qml:371`).
- **Refresh time grows with every wedged server.** Snapshots run one after
  another, 2 s each (`:393-411`). Three slow servers on a remote host use up
  most of its 8 s ssh limit, and the whole host shows as down.

**It acts on the wrong thing**
- **A refresh can change which agent is selected.** The cursor is a row number,
  and the rows re-sort by agent state on every poll. `rebuild()` only clamps the
  number and leaves `column` unclamped (`HerdrModel.qml:217`). If you move the
  cursor before the first answer arrives, it is reset to `bestRow()`
  (`:211-216`): moving never sets `cursorPlaced`.
- **The confirm dialog acts on a copy taken when it opened.** `confirmPending()`
  uses the session object from `ask()` (`HerdrModel.qml:336`, `:350`), so a
  session that started in the meantime is still treated as stopped, and Delete
  is sent to it. Closing the menu does not close the dialog.
- **Kill finds its server loosely.** The socket is matched by an unanchored
  `index()` and the first `pid=` on the `ss` line is taken. `grep -qz server`
  matches any argument containing "server". Those checks run once, not again
  before each signal (`bin/herdr-sessions:830-888`).
- **Any herdr process other than `server` is taken as a window of the default
  session,** for example `herdr agent prompt`, `--session=foo` or `-s foo`
  (`:286-311`).
- **Changing the prompt target mid-wait mixes up replies.** Pressing `a` on
  another agent while a prompt is waiting retargets it, and the first reply
  shows under the second agent's title (`Menu.qml:109-128`).

**It hides failures**
- **Errors are dropped.** Open and focus close the surface before their result
  arrives (`HerdrModel.qml:272-273`, `:290-291`); `n` does the same
  (`Menu.qml:145-147`). An invalid name returns without a word (`:583`).
  Unparseable output clears `actionError` (`:880`), the exit code is ignored
  (`:884`), and reopening clears the error again (`:798`). Focus failures end in
  `|| true`.
- **Some things report success without checking.** The terminal launcher is
  backgrounded and returns 0 (`bin/herdr-sessions:624`). A failing
  `hyprctl dispatch` still prints `ok:true`, because `show_session || die` turns
  off `set -e` inside the function (`:577-582`, `:632`).
- **The prompt text is lost on failure.** It is cleared on submit, before the
  result is known (`Menu.qml:187`). An unreachable host, or an agent waiting on a
  question, throws away what you typed.
- **One malformed snapshot clears the live details of every running session.**
  The merged object is validated as a whole and replaced by `{}`
  (`bin/herdr-sessions:442`). Rows stay, but read "no agents". A snapshot that
  timed out reads the same way, with `ok:true`.
- **An agent the badge counts can have no row.** Agents with empty titles are
  counted (`:484`) but filtered out (`:501`). A blocked one colours the badge
  but cannot be reached.
- **The caps don't bound the output.** Sessions beyond the count or byte cap
  still come out as running with 0 agents (`:397-405`, `:456`). `dropped` is
  never reported. Lengths are counted in characters, not bytes (`:401`, `:809`).
- **Stale data looks current.** Remote rows from the last open are redrawn on
  reopen, and a host reads "down" before its first answer (`HerdrModel.qml:224`).
  Reopening while the old ssh is still exiting marks a healthy host down
  (`:806-809`, `:859`). Hosts removed from `herdr.json` stay until the next
  rebuild. A failed local poll keeps old counts in the tooltip (`:787`).

**Smaller**
- Demo mode still lists real remote sessions (`bin/herdr-sessions:932`).
- The prompt text is in herdr's argv (`:778`, `:785`), although the comment says
  it never is. `herdr agent prompt` takes the text only as an argument, as its
  `--help` shows. The reply screen goes through `jq --arg` and can exceed the
  per-argument limit (`:820`).
- `cleanTitle()` strips leading CJK, Cyrillic and Greek text ("修复 API" becomes
  "API"). The attention tie-break picks the first agent although its comment
  says nobody (`HerdrModel.qml:638`, `:751`). Both were reproduced.
- While an agent is done and unseen, a closed local model keeps polling every
  5 s instead of every 20 s (`HerdrModel.qml:92`, `:906`).

Left to #23: the `replyFrom()` reply parser, which also cuts replies at
Markdown `>` lines, because #23 replaces it with a raw excerpt.

## Proposed outcome

- **Every action has a bounded duration,** locally and over ssh, child
  processes included. When an action runs out of time, the panel or menu says
  which one.
- **No action disappears.** One that cannot run now says so, and kill is never
  blocked by another action.
- **The cursor stays on the agent or session you chose** across refreshes, and
  from the moment the menu opens. If that item disappears, it moves to the
  nearest one, and the button column stays valid.
- **The confirm dialog acts on the session as it is now,** and closes with the
  menu.
- **Kill checks, immediately before each signal, that the process is still
  that session's own herdr server** (same socket, same process start time).
  Amended 2026-11-16, decision A: bash cannot signal atomically, so a PID
  reused in the microseconds between check and signal is out of scope.
- **Every failure in the lists above can be seen** in the menu or the pinned
  panel. That includes failures from open, focus, new and prompt, and a
  terminal that didn't start. Text typed for `n` or `a` survives a failure.
- **A server that can't be read is shown as unreadable, not as empty.** Other
  sessions keep their agents, and every agent the badge counts can be reached.
- **Refresh time doesn't grow with each wedged server,** and a remote host isn't
  reported down because some of its servers are slow.
- **Rows from the last time are marked as checking** until their host answers,
  and removed hosts go when `herdr.json` changes.
- **Demo mode shows nothing real.**
- **Titles keep their text in every script.**
- **The tie-break does what its comment says.**
- **Polling slows down** once nothing is working.
- **The README and comments say where the prompt text goes.**
- **Every item above has an automated test against fakes.**

## Affected users and systems

- **Users:** everyone using the menu or the bar panel, most of all with several
  sessions or remote hosts.
- **Files:** `HerdrModel.qml`, `Menu.qml`, `bin/herdr-sessions`, the tests and
  `README.md`. `Card.qml` and `Panel.qml` only where error lines or cursor
  identity need them.
- **Hosts:** p620 and razer (razer is the remote host), through the usual
  nixarchy pin bump.

## Constraints

- **No new features or visual changes.** Those are #23; herdr-core is #22.
- **Keep the existing defences:** shape checks on both ends, byte caps, `--`
  and `%q` for ssh, `BatchMode=yes`, PlainText. The script is still piped over
  ssh, with nothing installed on remote hosts (decided 2026-11-16).
- **Remote hosts keep `herdr.json` + ssh** (decided 2026-11-16).
- **No test touches a real herdr server.**
- **Merge with a merge commit.**

## Open questions

1. **A second action while one is running:** queue it, or refuse it with a
   visible "busy" line? Recommendation: refuse, but never let it block kill.
   Codex and agy both agree: a queued focus or delete runs after the rows have
   changed.
2. **Prompt text in argv:** accept it and correct the README and comments, or
   drop the prompt feature? Recommendation: correct the claim. herdr's CLI is
   the limit, these are single-user machines, and #22 sends prompts to
   herdr-core agents through `hc send`. Codex and agy agree.

Resolved on approval (2026-11-16): both recommendations taken.

How snapshots are collected (in parallel, how many at once, which deadline) is
left to the spec.
