# Plan: actions never hang, the cursor stays on what you picked, failures say why

Closes #20 on branch `fix/20-robustness`. The base is master at `5bb2796`,
plus this task's artifact commits. Line numbers below are on `2e1c3f4`; they
are the same in the code on this branch.

## Approved decisions (copied from the spec, so this plan stands alone)

- **D0: script ground rules.** `set -euo pipefail` stays.
  - Every command that may fail is checked where it runs (`if`, `|| rc=$?`,
    `|| true`). Never rely on errexit inside a function called from a
    condition.
  - `show_session`'s window lookup (`bin/herdr-sessions:564`) gets `|| true`.
  - Exit 124 and exit 137 both mean "timed out".
- **D1: hard deadlines.**
  - Add `bounded() { local s=$1; shift; timeout -k 1 "$s" "$@"; }`, and have
    `ssh_run` (`:151`) use it.
  - Limits:

    | Call | Where | Limit |
    |---|---|---|
    | focus | `:658` | 4 s |
    | `agent get` / `agent read` after a prompt | `:804-806` | 4 s |
    | `socket_of` | `:850` | 4 s |
    | `session delete` | `:903` | 8 s |
    | `hyprctl` | `:237`, `:577-588` | 2 s |
    | `pgrep` | `:262` | 2 s |

  - A timeout ends in `die "timed out: <what>"`.
  - `remote_action` (`:910`) maps ssh exit 124/137 to
    `timed out: <action> on <host>`.
  - Prompt: the 300 s wait running out gives `ok:true, status:"timeout"`. A
    timeout in the `agent get`/`agent read` that follow gives
    `die "timed out: reading the reply"`.
  - Remote `new` polls until `$SECONDS` reaches 30, starting a poll only if
    8 s still fit before that.
- **D2: busy and kill.**
  - `run()` and `newSession()` set
    `actionError = "busy: <action> is still running"` and return `false`; they
    return `true` when they start.
  - Kill uses its own `killProc`, with its own `killPendingKey`.
  - Both processes write one `actionError`, and the last completion wins.
- **D3: one completion per run.**
  - stdout is stored in `onStreamFinished` and the exit code in `onExited`;
    whichever arrives second calls `complete()`.
  - A `Process` is never restarted before its previous `onExited`.
  - Failure means unparseable output, `ok:false`, or a non-zero exit.
  - `dismissOnSuccess` for open and focus: `dismiss()` only on success, and a
    pinned panel never dismisses.
  - `n` keeps the line open and read-only while running. On success it closes;
    on failure it re-enables the line with the text kept and the error shown.
    An invalid name sets `actionError`.
  - `show_session` returns 2 when the launcher exited non-zero within 0.3 s
    (`die "the terminal exited at once"`), and 3 when `hyprctl dispatch` failed
    (`die "could not focus the window"`). Limitation: this only catches the
    first process, and the README says so.
  - Focus `|| true` (`:656-658`) becomes `timed out: focus` or
    `herdr could not focus that pane`.
- **D4: cursor identity.**
  - `rowKey(sessions,row)`: `agentKey(session,pane)` for an agent row,
    `sessionKey(session)+"\u0000"` for a session row.
  - `navRowsFor(all)` is a plain function, and the `navRows` binding calls it.
  - `rebuild()`:
    1. Compute `oldKey` from the current sessions and rows.
    2. Build the new rows.
    3. Find `oldKey` in them.
    4. Assign `sessions`, then `cursor` (the found index, else the old index
       clamped).
    5. Call `clampColumn()`.
  - `moveCursor`, `moveColumn`, `cycleColumn`, `cursorToAgent` and
    `cursorToSession` set `cursorPlaced = true`.
- **D5: confirm.**
  - `confirmPending()` looks up the current session by `sessionKey`. If it is
    gone, or no longer running (kill), or running now (delete), it does nothing
    and sets `"<label> changed; nothing done"`.
  - When `opened` goes false, `closeConfirm()` runs, and `Menu.close()` clears
    `promptConfirmOpen`.
- **D6: kill (decision A).**
  - `server_pid_for`:
    - Use the `ss -lpxn` line where some whitespace field equals the socket
      path exactly.
    - Walk every `pid=N` on it.
    - Accept a PID when `/proc/N/comm` is `herdr` and line 2 of
      `tr '\0' '\n' < /proc/N/cmdline` is exactly `server`.
    - Record the start time: cut `/proc/N/stat` after the last `") "` (`##`),
      then take field 20.
  - `parent_pid` (`:215`) switches to the same `##` cut.
  - `same_process pid start` runs immediately before TERM and before KILL. A
    mismatch means the server already exited, so `{"ok":true}`.
  - The two wait loops become one `wait_gone`.
  - A PID reused in the microseconds between check and signal is out of scope.
- **D7: windows.** `session_in_args` (`:283`):
  - It recognises `--session X|=X` and `--remote X|=X`, and skips any other
    word starting with `-`.
  - The first word that is neither a flag nor a flag's value decides:
    `session attach X` is a client of X; anything else is not a client.
  - No such word means a client, as now.
  - Test 7 stays green.
- **D8: snapshots.**
  - `LIST_BUDGET=6` s from the start of `cmd_list`, counting the 4 s session
    list.
  - Each snapshot's limit is `min(2, remaining−1)`; none starts with under
    1.5 s left.
  - `SNAPSHOT_JOBS=4`. Job PIDs go in an array, waited on with
    `wait -n || true`.
  - Each job projects its snapshot with one jq:
    - `agents`, `workspaces` and `tabs` are arrays of objects.
    - Strings are coerced with `tostring`, and `seq` with `tonumber? // 0`.
    - On failure, the job writes no file.
  - The merge reads only the projected files. The whole-object check at `:442`
    goes.
  - `RUN_DIR` is a global from `mktemp -d` under `$XDG_RUNTIME_DIR`, else
    `/tmp`, with `umask 077`.
  - A global trap on `EXIT INT TERM HUP` kills and waits for the jobs, then
    removes `RUN_DIR`.
  - A running session without a projected file is emitted as
    `readable:false`. `countLabel` shows "unreadable", `unreadableCount` is
    counted in `rebuild()`, and the tooltip names it.
- **D9: agents.**
  - Untitled agents are kept, titled `"untitled agent"` (`:501`).
  - Counts are taken after the sort and the 500 cap (`:484-488`, `:516`), and
    `hiddenAgents` is emitted.
  - `countLabel` adds "(N not shown)".
- **D10: caps.**
  - `session_exists` (`:671`) reads `herdr session list --json` directly:
    `bounded 4` locally, `ssh_run` remotely.
  - Output is capped with `.[0:$sessionCap]` after the sort, plus `hidden: N`,
    and Card's error line shows "N sessions not shown". The unused `dropped`
    counter is removed.
  - Final output over `TOTAL_BYTE_CAP` locally gives
    `die "session list too large to show"`.
  - Length-comparing functions (`cmd_list`, `over_byte_cap`) declare
    `local LC_ALL=C`.
  - The screen is cut with `head -c` (`:809`) and reaches jq via
    `jq -Rs --arg status` (`:820`).
- **D11: stale data.**
  - `stateOfHost` returns `"checking"` before the first answer. `hostState` is
    reset on open, and `hostSummary` draws checking as `…`.
  - Kill and delete on a host that is checking or down are refused with
    `"<host> not checked yet"`.
  - `pollGen` goes up on close. Each host-poll delegate copies it when it
    starts, and `complete()` ignores runs from older generations.
  - `cmd_list_remote` runs ssh as a direct background child with a TERM trap.
    The remote side is not signalled; it ends within its own `LIST_BUDGET`.
  - `applyHosts(list)` prunes `hostSessions` and `hostState`, then calls
    `rebuild()`. `hostsFile.onLoaded` and `onLoadFailed` call it.
  - A failed local poll keeps the rows, sets `reachable = false`, and
    `tooltipText()` shows `"Herdr: " + errorText`.
- **D12: demo.** `list` (`:932`) checks `demo_on` before `$HOST`. Demo mode
  with `--host` prints `{"ok":true,"error":"","sessions":[]}`.
- **D13: prompt.**
  - `submitPrompt` clears `newField` only on success.
  - `beginInput` refuses while `promptProc.running`: "a prompt is still
    waiting; Esc stops waiting".
  - The field stays read-only until the cancelled run's `onExited`.
  - The README, `Menu.qml:228` and `bin/herdr-sessions:728` say the text
    crosses the panel and ssh on stdin, but is an argument to herdr.
- **D14: display logic.**
  - `cleanTitle` strips only U+2800-28FF, U+2500-257F, `✳✻●◐◓◑◒•` and
    spaces at the start.
  - `updateAttention` sets `tied` on an equal `seq`, and then nobody blinks.
  - The poll interval (`:906`) uses `blockedCount > 0 || workingCount > 0`.

## Repo traps (apply to every step)

- **The script is piped to remote hosts as `bash -s`:** `$SCRIPT` is empty
  there. It must stay one self-contained file, and it may assume only bash, jq,
  herdr, ss, grep, awk, `timeout` and `/proc`. No python.
- **CI runs `bash -n` and `shellcheck` on `bin/*` and `tests/herdr-sessions.sh`.**
  New code must pass shellcheck, or carry a one-line `# shellcheck disable=`
  with a reason, as the existing code does.
- **Tests never touch a real herdr, ssh or Hyprland.**
  - Fakes live in `tests/herdr-sessions.sh`, steered by `FAKE_*` variables.
  - The only new production seam is `HERDR_TEST_PROC`, defaulting to `/proc`.
- **`tests/session-actions.cjs` extracts functions by the regex
  `'  function NAME\\([^]*?\\n  \\}'`.** Keep new testable logic in top-level
  functions with two-space indentation, and the closing `}` alone on a line.
- **Every `Text` in QML uses `textFormat: Text.PlainText`.** Error strings may
  contain session names.
- **Omarchy's key handler takes lowercase `k` and `x` before the panel sees
  them.** Change no key bindings in this task.
- **`hyprctl dispatch` takes Lua (`hl.dsp.focus({...})`).** Keep the shape
  checks on the values spliced into it.
- **jq start-up is the main cost per poll.** D8 adds one jq per running
  session, inside the parallel jobs. Add no other jq to the per-poll path.
- **Implementers never stage, commit, push or switch branches.** The lead
  commits after each step.
