## Approved decisions (copied from the spec, so this plan stands alone)

- **D0: script ground rules.**
  - `set -euo pipefail` stays.
  - Every command that may fail is checked where it runs (`if`, `|| rc=$?`,
    `|| true`). Never rely on errexit inside a function called from a
    condition.
  - `timed_out() { [[ $1 == 124 || $1 == 137 ]]; }`: both codes mean timed out.
  - **The window lookup is best effort.** `window_map` (`:233`) and its callers
    never `die`:
    - a timeout or failure in `hyprctl clients` (`:237`) or `pgrep` (`:262`)
      yields no output and status 0;
    - `show_session`'s lookup (`:564`) gets `|| true`;
    - a missing window means a new one is opened, as now.
- **D1: hard deadlines.**
  - `bounded() { local s=$1; shift; timeout -k 1 "$s" "$@"; }`, and `ssh_run`
    (`:148-152`) uses it.
  - **Limits and timeout messages:**

    | Call | Where | Limit | On timeout |
    |---|---|---|---|
    | `herdr agent focus` | `:658` | 4 s | `timed out: focus` |
    | `agent get` / `agent read` after a prompt | `:804-806` | 4 s | `timed out: reading the reply` |
    | `socket_of` → `herdr session list` | `:850` | 4 s | `timed out: finding the server` |
    | `herdr session delete` | `:903` | 8 s | `timed out: delete` |
    | `hyprctl dispatch` | `:577-588` | 2 s | `show_session` returns 3 → `could not focus the window` |
    | `hyprctl clients` | `:237` | 2 s | best effort (D0) |
    | `pgrep` | `:262` | 2 s | best effort (D0) |
    | `session_exists` list | `:671` | 4 s | `timed out: checking the name` |

  - **Remote actions:** `remote_action` (`:910-917`) keeps ssh's exit code, and
    turns a timeout into `timed out: <action> on <host>`.
  - **Prompt:**
    - The wait (`:785`) running out with 124 or 137 is not a failure. The
      result is `ok:true, status:"timeout"`, and the menu shows "still working
      after 5 min" on the line above the excerpt.
    - The `agent get` and `agent read` that follow are not allowed to time out:
      a timeout there gives `timed out: reading the reply`.
  - **Remote `new`:**
    - It polls until `$SECONDS` reaches `NEW_DEADLINE` (30, or the value of
      `HERDR_TEST_NEW_DEADLINE`).
    - Each poll starts only if 8 s still fit before the deadline.
    - Worst case: about 46 s.
- **D2: busy and kill.**
  - `run()` and `newSession()` set `actionError = "busy: <action> is still
    running"` and return `false`; they return `true` when they start.
  - Kill uses its own `killProc`, with its own `killPendingKey`.
  - There is one `actionError`, and the last completion wins.
- **D3: one completion per run.**
  - **Which processes:** `actionProc`, `killProc`, `promptProc` and every host
    poll.
  - **How a run completes:**
    - `onStreamFinished` stores stdout and `onExited` stores the exit code.
      Whichever comes second calls `complete()` exactly once for that run.
    - A `Process` is never restarted before its previous `onExited`.
  - **What counts as failure:** unparseable output, `ok:false`, or a non-zero
    exit.
  - **The error line:** `actionError` is cleared only by a success or by
    opening the surface again.
  - **When the surface closes:**
    - Open and focus pass `dismissOnSuccess`.
    - `complete()` calls `dismiss()` only on success.
    - `dismiss()` already does nothing on a pinned panel (`:265-267`).
  - **`n`:**
    - While the action runs, the line stays open and read-only.
    - On success it closes the line and the menu.
    - On failure it re-enables the line with the text kept, and shows the
      error.
    - An invalid name sets `actionError = "not a valid session name"`
      (`:583`).
  - **Script side:**
    - `show_session` returns 2 if the launcher has exited non-zero by 0.3 s
      (`die "the terminal exited at once"`).
    - It returns 3 if `hyprctl dispatch` failed or timed out
      (`die "could not focus the window"`).
    - Limitation: only the first process of the launch chain is checked; the
      README says so.
  - **Focus** (`:656-658`): `|| true` becomes a checked call: `timed out:
    focus`, or `herdr could not focus that pane`.
- **D4: cursor identity.**
  - `rowKey(sessions,row)`: `agentKey(session,pane)` for an agent row, and
    `sessionKey(session)+"\u0000"` for a session row.
  - `navRowsFor(all)` is a plain function, and the `navRows` binding (`:373`)
    calls it.
  - `rebuild()` resolves the key against the old rows before replacing
    anything:
    1. Compute `oldKey` from the current `sessions` and `navRows`.
    2. Build `rows = navRowsFor(all)`.
    3. Find `oldKey` in `rows`.
    4. Assign `sessions`, then `cursor`: the found index, or else the old index
       clamped to the new length.
    5. Call `clampColumn()`.
  - `moveCursor`, `moveColumn`, `cycleColumn`, `cursorToAgent` and
    `cursorToSession` set `cursorPlaced = true`.
- **D5: confirm.**
  - `confirmPending()` (`:349`) looks up the current session by `sessionKey`.
    If it is gone, or no longer running (kill), or running now (delete), it
    does nothing and sets `"<label> changed; nothing done"`.
  - When `opened` goes false, `closeConfirm()` runs, and `Menu.close()`
    (`Menu.qml:75`) clears `promptConfirmOpen`.
- **D6: kill (decision A).**
  - **Finding the server:** `server_pid_for` (`:830-847`):
    - Take the `ss -lpxn` line where some whitespace field equals the socket
      path exactly.
    - Walk every `pid=N` on it.
    - Accept the first PID whose `$PROC/N/comm` is `herdr` and where line 2 of
      `tr '\0' '\n' < $PROC/N/cmdline` is exactly `server`.
    - Print `pid start`. The start time is field 20 after cutting
      `$PROC/N/stat` past the **last** `") "` (`${line##*") "}`).
  - `parent_pid` (`:215`) gets the same `##` cut.
  - `PROC=${HERDR_TEST_PROC:-/proc}`.
  - **Signalling:** `same_process pid start` runs immediately before TERM and
    before KILL. A mismatch means the server already exited, so `{"ok":true}`.
    The wait loops become one `wait_gone`.
  - A PID reused in the microseconds between the check and the signal is out
    of scope.
- **D7: windows.** In `session_in_args` (`:283-311`):
  - It recognises `--session X|=X` and `--remote X|=X`, and skips any other
    `-…` word.
  - The first word that is neither a flag nor a flag's value decides:
    `session attach X` is a client of X; anything else is not a client.
  - No such word means a client of the default or named session.
- **D8: snapshots.**
  - **Budget:**
    - `LIST_BUDGET=6`, measured with the whole-second `$SECONDS` from the
      start of `cmd_list`. The 4 s session list counts against it.
    - A snapshot starts only if `remaining >= 2`, with the limit
      `min(2, remaining - 1)`, so it is always ≥ 1 s. Never `timeout 0`: that
      disables the timeout.
  - **Jobs:**
    - At most `SNAPSHOT_JOBS=4` at once. Their PIDs go in the global
      `JOB_PIDS`, and the script waits with `wait -n || true`.
    - Each job keeps the per-snapshot byte cap (`head -c cap+1`, then the size
      check).
    - It projects the snapshot with one jq into exactly
      `{"<name>": {version, agents, workspaces, tabs}}` (deviation, step 2: `version` kept because the merge still emits it): arrays of objects, strings
      coerced with `tostring`, `seq` with `tonumber? // 0`.
    - It writes `$RUN_DIR/snap.<name>.json` atomically (`> tmp && mv`).
    - On any failure, including the cap, it writes nothing.
  - **Merge:**
    - The existing merge jq reads the files with
      `--slurpfile snapshotsIn <(cat "${files[@]}")`, where `files` is
      collected with `nullglob`. With no files, it reads `/dev/null`.
    - Then `($snapshotsIn | add // {})`.
    - No extra jq on the poll path. The whole-object check at `:442` goes.
  - **Unreadable sessions:**
    - A running session without a file is `readable:false`. That covers a
      failed, oversized or skipped snapshot.
    - `countLabel` shows "unreadable"; `rebuild()` counts `unreadableCount`;
      the tooltip names it.
- **D9: agents.**
  - Untitled agents are kept, as "untitled agent" (`:501`).
  - The counts (`:484-488`) are taken after the sort and the 500 cap (`:516`),
    and `hiddenAgents` is emitted.
  - `countLabel` adds "(N not shown)".
- **D10: caps.**
  - `session_exists` (`:671-680`) reads `herdr session list --json`
    directly: `bounded 4` locally, `ssh_run` remotely.
  - The output is capped with `.[0:$sessionCap]` after the sort, with
    `hidden: N`. Card's error line shows, in order of precedence:
    `actionError`, then `errorText`, then "N sessions not shown".
  - The `dropped` counter goes.
  - Final local output over `TOTAL_BYTE_CAP` gives
    `die "session list too large to show"`.
  - `local LC_ALL=C` in `cmd_list` and `over_byte_cap` (`:82`).
  - The screen is cut with `head -c` (`:809`); a cut UTF-8 sequence becomes
    U+FFFD through `jq -R`. It reaches jq through `jq -Rs --arg status`
    (`:820`).
- **D11: stale data.**
  - **Checking state:**
    - `stateOfHost` returns `"checking"` before the first answer, and
      `hostState` is reset on open.
    - `hostSummary` draws checking as `…`.
    - Kill and delete on a host that is **checking or down** are refused:
      `"<host> not checked yet"`.
  - **Old poll results:**
    - `pollGen` increases on close. A host poll copies it when it starts, and
      `complete()` ignores runs from an older generation.
    - Reopening while an old poll is still exiting sets that delegate's
      `restartPending`. Its `onExited` then starts a fresh run if the menu is
      open.
  - **Remote listing:**
    - `cmd_list_remote` runs ssh as a background child registered in
      `JOB_PIDS`, under the shared trap (D8). There is no second trap.
    - The remote side is not signalled; it ends within its own `LIST_BUDGET`.
  - **Hosts file:** `applyHosts(list)` prunes `hostSessions` and `hostState`,
    then calls `rebuild()`.
  - **Unreachable:** a failed local poll keeps the rows and sets
    `reachable = false`, and the tooltip shows `"Herdr: " + errorText`.
- **D12: demo.**
  - The `list` dispatch (`:930-934`) checks `demo_on` before `$HOST`.
  - Demo mode with `--host` prints `{"ok":true,"error":"","sessions":[]}`.
  - `demo_list` (`:186`) emits `readable:true`.
- **D13: prompt.**
  - `submitPrompt` clears the text only on success.
  - `beginInput` refuses while `promptProc.running`: "a prompt is still
    waiting; Esc stops waiting".
  - The field stays read-only until the cancelled run's `onExited`.
  - The docs say the text crosses the panel and ssh on stdin, but is an
    argument to herdr.
- **D14: display logic.**
  - `cleanTitle` strips only U+2800-28FF, U+2500-257F, `✳✻●◐◓◑◒•` and spaces
    at the start.
  - `updateAttention` sets `tied` on an equal `seq`, and then nobody blinks.
  - The poll interval (`:906`) uses `blockedCount > 0 || workingCount > 0`.
    The badge colour still uses `badgeActive`.

## Shared run directory (D8, D11), used by steps 2 and 3

```bash
RUN_DIR="" ; JOB_PIDS=()
run_dir_init() {               # idempotent; called by cmd_list and cmd_list_remote
  [[ -n $RUN_DIR ]] && return 0
  local base=${XDG_RUNTIME_DIR:-/tmp}
  RUN_DIR=$(umask 077; mktemp -d "$base/nixarchy-herdr.XXXXXX") || return 1
  trap run_dir_cleanup EXIT
  trap 'exit 143' TERM INT HUP   # exit runs the EXIT trap once
}
run_dir_cleanup() {
  local p
  for p in "${JOB_PIDS[@]}"; do kill -TERM "$p" 2>/dev/null || true; done
  for p in "${JOB_PIDS[@]}"; do wait "$p" 2>/dev/null || true; done
  [[ -n $RUN_DIR ]] && rm -rf -- "$RUN_DIR"
}
```

`cmd_prompt`'s own TERM trap (`:788`) is unchanged, because the prompt path
never calls `run_dir_init`.

  there. It stays one self-contained file, and may assume only bash ≥ 4.3, jq,
  herdr, ss, grep, awk, `timeout` and `/proc`. No python.
- **CI runs shellcheck on `bin/*` and `tests/herdr-sessions.sh`.** New code
  passes it, or carries a one-line `# shellcheck disable=` with a reason.

  - The only production test seams are `HERDR_TEST_PROC` and
    `HERDR_TEST_NEW_DEADLINE`, each with a production default.
- **`$SECONDS` is whole seconds,** and `timeout 0` means no timeout.
- **`tests/session-actions.cjs` extracts functions with the regex
  `'  function NAME\\([^]*?\\n  \\}'`.** New testable logic goes in top-level
  functions indented two spaces, with the closing `}` alone on its line.
- **Every QML `Text` uses `textFormat: Text.PlainText`.**
- **Omarchy's key handler takes lowercase `k` and `x`.** Change no key bindings
  in this task.
- **`hyprctl dispatch` takes Lua (`hl.dsp.focus({...})`).** Keep the shape
  checks on spliced values.
- **jq start-up is the main cost per poll.** Only D8's one jq per running

- **Hand steps over one at a time.** Steps 1, 2 and 3 edit the same script;
