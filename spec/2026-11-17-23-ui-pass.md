# Spec: a readable, discoverable, adjustable panel and menu

- **Base:** master `7b678da` (plugin 1.1.0).
- **Revision 2,** after the Codex review (gpt-6.1-sol). Codex's 13 findings
  were all checked against the code and taken. The agy review was not
  obtained: "UNAVAILABLE (code 503): No capacity available for model
  gpt-oss-120b-medium".

**The intent's open questions**, settled here:

| # | Question | Decision |
|---|---|---|
| 1 | Badge number | Agents that need you; `!` shown alongside |
| 2 | Text size | The recommended keys and range |
| 3 | Column cursor | Dropped |
| 4 | `n` | Labelled; the row decides |
| 5 | Shared model | A follow-up issue |

## Design

### U1. The badge: always shown when you're needed, one meaning

Files: `HerdrModel.qml`, `Panel.qml`.

- **`needCount`.** A new readonly property, `blockedCount + doneCount`.
  `doneCount` already means "done and not seen". For app agents it follows
  herdr-app's seen state (#22, #27).
- **`badgeShown`** becomes `appMark || badgeActive`.
  - Neither `runningCount > 0` nor `reachable` is required any more.
  - The counts come from the rows actually drawn, so they hold:
    - an hc-only machine's agents;
    - app agents while the classic list fails (`reachable` false,
      `HerdrModel.qml:1222`, set apart from app collection at `:1191`).
  - A failed classic list on its own still shows no badge. Its error stays
    in the tooltip and the error line, as today.
- **Badge text** (`Panel.qml:254`):
  - `needCount` when above 0, with `!` appended while `appMark` holds
    (`2!`);
  - `!` alone when nothing needs you and herdr-core is stale;
  - otherwise empty, drawn as a small dot in the state's colour, so
    "working" still shows without a number.
- **Badge size.** The badge stays at the bar's own size. `textScale` is for
  the panel and the menu, not the bar (`Panel.qml:257` keeps
  `Style.bar` sizing).
- **Colour** comes from `priority()` (U9):
  - urgent for blocked or stale;
  - finished for done;
  - working for working;
  - nothing when idle.
- **Tooltip** (`tooltipText()`) lists every non-zero part:
  - servers, agents, waiting on you, finished and working;
  - "herdr-core not reachable" while stale;
  - the classic error when unreachable.

### U2. Text size from the keyboard

Files: `HerdrModel.qml`, `Card.qml`, `Menu.qml`, `Panel.qml`.

- **State.**
  - `HerdrModel.textScale` becomes `property real textScale: 1.0`. The
    `host.textScale` fallback goes.
  - `Menu.qml:64`'s fixed `textScale` goes. Menu and Card read the model's.
- **Steps.**
  - `textBigger()`, `textSmaller()` and `textReset()` clamp to `[0.8, 1.6]`
    in steps of 0.1.
  - Each result is rounded to one decimal, so the value never drifts.
- **Memory.** The value lives in `$XDG_CACHE_HOME/omarchy-herdr/text-scale`
  (`$HOME/.cache` when unset), as a bare number. It uses the same cache
  directory as `bin/herdr-sessions:44`.
  - **Reading.** A `FileView` follows the existing pattern at
    `HerdrModel.qml:1289-1296`: `watchChanges: true` and
    `onFileChanged: reload()`. `onLoaded` parses the text.
    - A number in `[0.8, 1.6]` is applied.
    - Anything else, an empty file, a missing file or a load error leaves
      the current value unchanged (1.0 at start).
  - **Writing.** Only a key press writes, with `setText` of the new value.
    A load never writes back, so there is no feedback loop.
    - **No stale overwrite.** The file is the one source of truth, and a
      load reads it after the write it follows.
    - **Rapid presses** step from the instance's current value, so none is
      lost on the pressing surface. If two surfaces press at the same
      moment, the last write wins and both converge on it through the
      watch.
  - **Missing directory.** `bin/herdr-sessions` creates the cache directory
    on every run. If a write still fails, the size applies for this session
    only, with no error line.
- **Keys.**
  - **Bare and Shifted keys** go through `Card.qml`'s `onTextKey` (`:102`).
    The shell's `PanelKeyCatcher` emits `textKey(text, modifiers)`
    (`Ui/PanelKeyCatcher.qml:54`, `:119-120`), so no `Keys.onPressed` is
    added. One there would replace the catcher's arrow handling
    (`Card.qml:686`).
    - `+` and `=` make text bigger, `-` smaller and `0` resets, when
      `modifiers` holds no more than Shift.
    - With Alt or Meta held, nothing happens.
  - **Ctrl chords** use QML `Shortcut` items:
    - `Ctrl+=`, `Ctrl++` and `Ctrl+Shift+=` make text bigger;
    - `Ctrl+-` makes it smaller;
    - `Ctrl+0` resets.

    Each surface gets them with `context: Qt.WindowShortcut`: the card
    (bar dropdown and pinned window) and the menu window. They work while
    the `n` or prompt input has focus.
  - **Inside the inputs,** bare `+ = - 0 ?` reach the `TextInput`, never the
    catcher, so `task-0`, `/tmp/c++` and `x=0` type as written. The inputs
    keep handling only Esc and Enter (`Menu.qml:464`).
- **What scales.**
  - Every `font.pixelSize` and icon `fontSize` in Card and Menu already
    multiplies `textScale`. The bar badge doesn't (U1).
  - The confirm overlay passes it to the dialog (U10).
  - The default card width (`Panel.qml:103`) and minimum width (`:104`)
    multiply it, as does the menu width (`Menu.qml:65`). All stay capped by
    the room on screen (`Panel.qml:366-370`, `Menu.qml:376`).
  - A pinned card the user resized keeps its `chosenWidth`, and its text
    elides more. A user's own width wins, and this is documented.
  - Spacing stays at `Style.space`.

### U3. Dim with alpha, not darker

Files: `Card.qml`, `Menu.qml`, `Panel.qml`, `HerdrModel.qml`.

- **Every** `Qt.darker(<x>.foreground, k)`, whether `root.`, `panel.` or
  `card.` foreground (17 calls), becomes `Qt.alpha(<x>.foreground, a)`.
  `Qt.alpha` was checked in this Quickshell: 0.5 in gives a = 0.5.
- **The full map,** with a ≈ 1/k:

  | k | 1.2 | 1.3 | 1.4 | 1.5 | 1.6 | 1.7 | 1.8 | 1.9 | 2.1 | 2.2 |
  |---|---|---|---|---|---|---|---|---|---|---|
  | a | 0.83 | 0.77 | 0.71 | 0.67 | 0.62 | 0.59 | 0.56 | 0.53 | 0.48 | 0.45 |

  The order of the steps is kept: dimmer stays dimmer.
- **Contrast is a test, not a hope.** A unit test blends each `a` over the
  card background of a dark theme and a light theme, then computes the WCAG
  contrast ratio. The themes are Omarchy's default and a light one, both
  read from `Commons.Color` values in the test.
  - Text with `a ≥ 0.53` must reach 4.5:1.
  - Fainter text, such as the footer and the grips, must reach 3:1.
  - Rows tinted with the accent are checked too.
  - A value that fails is raised until it passes, and the table is updated.

### U4. Keys you can find

Files: `Card.qml`, `Menu.qml`, `bin/herdr-menu-keys`.

- **A footer per surface,** one line, elided, caption size, faint:
  - **menu:** `n new · a ask · i stop · x end · ± size · ? keys`;
  - **bar dropdown and pinned card:** `o open · i stop · x end · ± size ·
    ? keys`. `n` and `a` do nothing there (`HerdrModel.qml:777-786`,
    `README.md:263`), so they aren't advertised.
- **`?`** starts `bin/herdr-menu-keys` as a detached `Process`. The surface
  closes first, so its exclusive keyboard focus doesn't stand in the
  picker's way. In the inputs, `?` stays literal.
- **The empty state** (`Card.qml:676`):
  - the menu: "No herdr sessions. Press n to start one.";
  - the bar surfaces: "No herdr sessions."
- **One destroy key, `x`** (the catcher's `deleteRequested`):
  - on a running classic session, it asks to kill the server;
  - on a stopped one, it asks to delete it;
  - on an app agent, it asks to end it, with the cascade.
- **`K` stays an alias of `x`.**
- **The key sheet** lists `x`, `K` ("same as x"), the size keys and `?`. It
  drops the column keys.

### U5. Drop the column cursor

Files: `HerdrModel.qml`, `Card.qml`.

- **Removed:**
  - `column`, `columnOpen`, `columnRow`, `columnDestroy`;
  - `lastColumnFor`, `moveColumn`, `cycleColumn`, `clampColumn`,
    `cursorInBody()`.
- **Their references, by line:**

  | File | Lines | What |
  |---|---|---|
  | `HerdrModel.qml` | `:696` | Enter's button branches |
  | `HerdrModel.qml` | `:711` | `cursorInBody` |
  | `HerdrModel.qml` | `:726`, `:736` | mouse cursor moves |
  | `HerdrModel.qml` | `:1270`, `:1282` | open and close resets |
  | `Card.qml` | `:428` | agent highlight |
  | `Card.qml` | `:606`, `:632`, `:645` | button highlights |
  | `Card.qml` | `onMoveRequested` | the `dx` branch |
  | `Card.qml` | `onTabRequested` | the whole handler |
- **What stays.** The buttons stay clickable with the mouse. `activateCursor()`
  keeps its row behaviour:
  - Enter on an agent lands on it;
  - on a session, it opens it;
  - on a stopped session, it starts it.
- **The source check** looks for the removed symbol names, not the word
  "column".

### U6. Keep the highlighted agent on screen

Files: `Card.qml`, `HerdrModel.qml`.

- **`HerdrModel.showRow(sessionIndex, agentIndex)`.** Both callers pass the
  agent index (`HerdrModel.qml:351` after a rebuild, `:684` after a move).
  `rebuild()` also calls it when the cursor's identity survived but its row
  index changed (`:343`).
- **`Card.showRow(si, ai)`:**
  1. If the session delegate isn't instantiated, run
     `positionViewAtIndex(si, ListView.Contain)` first.
  2. On `Qt.callLater`, take the agent row from the session delegate's
     `Repeater` (`Card.qml:385`). Map its rectangle into `list.contentItem`.
  3. Let `top = r.y`, `bottom = r.y + r.height` and `view = [contentY,
     contentY + height]`:
     - `top < contentY`: set `contentY = top`;
     - `bottom > contentY + height`: set `contentY = bottom - height`;
     - a row taller than the view: align its top.
  4. Clamp `contentY` to `[originY, originY + contentHeight - height]`.
- **When `ai < 0`** (a session row), today's
  `positionViewAtIndex(si, ListView.Contain)` is used.

### U7. `n`: say what it will make, and where

File: `Menu.qml`.

- **Behaviour is unchanged:** the row under the cursor decides the host and
  the kind (intent Q4).
- **The label** (`Menu.qml:441-449`) reads "New session on <host>" or "New
  space on <host>".
  - `<host>` is the row's host, or this machine's hostname.
  - The label takes its implicit width up to half the input row. The host
    name is never elided (hostnames are short). A long label elides the
    leading words ("New session") first.
- **Placeholders:**
  - `newField`: "name, then optionally a folder";
  - the prompt input: "message to <agent title>".
- **Accessibility.** `newField`'s `Accessible.name` is the label text in both
  modes.

### U8. Prompt reply, layer, motion, focus and accessibility

Files: `Menu.qml`, `Panel.qml`, `Card.qml`.

- **The reply.**
  - `replyFrom()` is deleted. The reply shows the last 40 lines of the
    returned output, in the theme's monospace font, with line breaks and
    indentation kept.
  - **Caps:**
    - at most 4000 characters, cut at a line start;
    - if the last line alone is longer, its last 4000 characters, with `…`
      in front.
  - **The reply box** is at most 40 % of the card's height, and scrolls.
- **While waiting,** the input line reads "waiting 12 s · Esc cancels",
  updated by a 1 s timer that runs only while waiting.
- **Layer.**
  - The pinned card moves from `WlrLayer.Overlay` to `WlrLayer.Top`
    (`Panel.qml:323`). It is persistent, so it should not cover a
    fullscreen window.
  - **D1: the menu stays on `WlrLayer.Overlay`** (`Menu.qml:354`). It is
    summoned by a key press, holds exclusive keyboard focus (`:355`), and
    closes on Esc.
    - On Top it would open *under* a fullscreen window while holding the
      keyboard: invisible, yet capturing keys.
    - Covering the screen while you asked for it is the expected behaviour
      of a summoned menu.
    - This narrows the approved intent ("the pinned card and the menu don't
      cover fullscreen windows") to the pinned card. It needs the owner's
      OK at spec approval.
- **The blink** (`Card.qml:487`).
  - Selection stays exactly as in `updateAttention()`
    (`HerdrModel.qml:998-1030`): newly wanting agents, the seq rule, ties
    going to nobody, and classic winning across scales.
  - **An episode** starts whenever `attentionKey` is set to a non-empty key.
  - **Expiry.** A single-shot 60 s `Timer`, restarted at each episode, sets
    `blinkExpired = true`. `blinking` becomes `attentionKey !== "" &&
    !blinkExpired`, and the dot stays lit.
  - **Ending.** Clearing `attentionKey` (it stopped wanting, or it vanished)
    stops the blink at once.
  - With `alwaysRunToEnd` (`Card.qml:490`), the last cycle may finish, so
    the limit is 60 s plus at most one cycle.
- **Pinning from the keyboard.**
  - When `p` pins (`togglePin` from a key), `pinWindow` skips `armTimer`'s
    300 ms delay (`Panel.qml:455-469`). It sets `focusArmed = true` at once,
    so `WlrLayershell.keyboardFocus` becomes `OnDemand` (`:325`), and the
    catcher takes `forceActiveFocus()`.
  - A pin restored at shell restart, or pinned by mouse, keeps today's
    no-focus-steal path.
- **Accessibility.**
  - `Accessible.focused`: on an agent row, when the cursor is that agent;
    on a session row, only when the cursor is the session row itself (not
    `cursorOnSession`, `HerdrModel.qml:744`, which includes its agents).
  - Icon buttons are named "Open session", "Kill server", "Delete session",
    "End agent", "Pin" or "Unpin".
  - The inputs are named per U7.

### U9. One priority rule

File: `HerdrModel.qml`.

- **`priority(c)`** returns `"blocked"`, `"done"`, `"working"` or `"idle"`
  for any object with `blocked`, `done` and `working` counts.
- **Who uses it:** `noteColor`, `statusColor`, `badgeColor` and `noteLabel`.
- **Each keeps its own guards and palette:**
  - a null note returns foreground;
  - `statusColor`'s stopped and idle shades become alpha (U3);
  - `badgeColor`'s stale check comes first and uses `working`, while rows use
    `workingForeground`.
- **`attentionRank`** keeps its own per-status table. It ranks single
  statuses, not counts.

## Alternatives rejected

- **Badge = running servers.** That number means something different from
  the blocked count, and hc-only machines have no servers.
- **The theme's `base-size`.** It's global and already exists; the owner
  asked for the panel.
- **Per-surface text sizes.** Confusing, and they buy nothing.
- **`Keys.onPressed` on the catcher for Ctrl chords.** It replaces the
  catcher's handler and loses the arrow keys (`Card.qml:686`).
- **`Qt.lighter` on light themes.** That needs theme detection; alpha works
  on both.
- **Keeping the column cursor.** Two ways to do one thing, with buttons on
  the wrong row.
- **`n` always local.** It removes the keyboard route to remote hosts and app
  spaces.
- **A Markdown renderer for replies.** Heavier than the raw excerpt the owner
  asked for.
- **The menu on Top.** A summoned menu would capture keys while invisible
  under a fullscreen window (D1).

## Risks

- **R1. Muscle memory.** Left/Right, h/l and Tab stop doing anything. The
  key sheet and the README say so, and `K` stays.
- **R2. Pinned card on Top under fullscreen.** It is hidden there, by
  design, and it never takes the keyboard unless clicked or pinned by key.
  - Checked in the `nixarchy-desktop` microVM with a throwaway fullscreen
    window.
- **R3. Width.** At 1.6x on a 1280 px screen, text elides more.
  - Checked by demo-mode screenshots at 0.8x, 1.0x and 1.6x, in the microVM
    and read-only on p620.
- **R4. The size file.** See the U2 rules. A file that's unreadable,
  unwritable or holds garbage can't break the panel; at worst the size
  doesn't persist.
- **R5. No badge on idle classic servers.** Intended. The tooltip and title
  keep the counts.
- **R6. Deploy.** New QML types need `omarchy-restart-shell` after the
  switch, announced on the agent bus first.
- **R7. Model-only tests can't prove keyboard delivery or compositor focus.**
  Those are checked live, as listed in Verification.
