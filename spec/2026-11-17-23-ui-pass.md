# Spec: a readable, discoverable, adjustable panel and menu

The base is master `7b678da` (plugin 1.1.0). The intent's six open questions
are settled here (U1–U12 below):

| Question | Answer |
|---|---|
| 1. The badge number | agents that need you; stale shown alongside |
| 2. Text size | the recommended keys and range |
| 3. The column cursor | dropped |
| 4. `n` | labelled; the row decides |
| 5. One shared model | a follow-up issue, not here |
| 6. The layer | Top, after a fullscreen check |

## Design

### U1. The badge: always shown when you're needed, one meaning (`HerdrModel.qml`, `Panel.qml`)

- **`needCount`** is a new readonly property: `blockedCount + doneCount`.
  `doneCount` already means "done and not seen". For app agents it follows
  herdr-app's seen state (#22 and #27).
- **`badgeShown`** becomes `appMark || (reachable && badgeActive)`.
  - The `runningCount > 0` condition goes, so a machine with only `hc` shows
    its agents.
  - A classic server that is merely up no longer shows a badge.
- **The badge text** (`Panel.qml:254`) becomes:
  - `needCount` when it is above 0, with `!` appended while `appMark` holds
    (for example `2!`);
  - `!` alone when nothing needs you but herdr-core is stale;
  - empty otherwise. An empty badge shows as a small dot in the state's
    colour, so "agents are working" still shows without a number.
- **The colour** comes from one function, `priority()` (U9):
  - urgent for blocked or stale;
  - finished for done;
  - working for working;
  - no badge when idle.
- **The tooltip** (`tooltipText()`) always lists, each part only when it is
  non-zero:
  - servers, agents, waiting on you, finished, working;
  - "herdr-core not reachable" while stale.
- **The title** (`titleText()`) is unchanged. It already counts servers and
  agents.

### U2. Text size from the keyboard (`HerdrModel.qml`, `Card.qml`, `Menu.qml`, `Panel.qml`)

- **State.**
  - `HerdrModel.textScale` stops being readonly. It is
    `property real textScale: 1.0`, and the `host.textScale` fallback goes.
  - `Menu.qml:64`'s fixed `textScale` goes. Menu and Card read the model's
    value.
- **Steps.** `textBigger()`, `textSmaller()` and `textReset()` clamp to
  `[0.8, 1.6]` in steps of 0.1. Each result is rounded to one decimal, so
  repeated steps don't drift.
- **Memory.**
  - The value is stored as a bare number in
    `$XDG_CACHE_HOME/omarchy-herdr/text-scale`, the cache directory
    `bin/herdr-sessions` already uses (`:44`).
  - Each model reads it through a `FileView` with `watchChanges: true`
    (the model already uses `FileView`, at `:1289`). The model writes it
    with `setText` after each step.
  - Every model on every surface reads the same file, so the bar's pinned
    card and the menu agree. A change in one reaches the others through the
    file watch.
  - A missing, unreadable or out-of-range value means 1.0.
- **Keys outside the inputs** (the card's key catcher):
  - `+` and `=` make text bigger, `-` smaller, `0` resets.
  - Ctrl with the same keys does the same.
  - Matching uses `event.text`, or `event.key` for Ctrl, so a shifted `+`
    works on any layout. No other modifier combination triggers it.
  - These go into `Card.qml`'s `onTextKey` (`:105`). The Ctrl chords go into
    a `Keys.onPressed` on the same catcher.
- **Keys inside the `n` and prompt input** (`Menu.qml:464`):
  - Only the Ctrl chords resize. They are handled before the input sees them,
    and accepted.
  - Bare `+ = - 0` stay literal, so `task-0`, `/tmp/c++` and `x=0` type as
    written.
- **What it scales.**
  - Every `font.pixelSize` and icon `fontSize` already multiplies
    `textScale`.
  - The confirm dialogs gain it (U10).
  - These widths multiply it, each still capped by the room on screen:
    - the card width, `Panel.qml:103` `cardWidth` and `:104` `cardMinWidth`;
    - the menu width, `Menu.qml:65`.
  - Spacing stays at `Style.space`. Text that still doesn't fit elides, as
    it does today.

### U3. Dim with alpha, not darker (`Card.qml`, `Menu.qml`, `Panel.qml`, `HerdrModel.qml`)

- **Text.** Every `Qt.darker(root.foreground, k)` used for text becomes
  `Qt.alpha(root.foreground, a)`. `Qt.alpha` was checked in this Quickshell:
  it returns a = 0.5 for 0.5.
  - The map is k 1.5 → a 0.72, k 1.7 → a 0.62, k 2.2 → a 0.48. Dimmer stays
    dimmer, on either theme.
- **Icons and grips.** Those using `Qt.darker` get the same treatment, so a
  light theme doesn't turn them black.
- **One table.** `HerdrModel` gets two named properties, `dim: 0.62` and
  `faint: 0.48`, so the factors aren't repeated.

### U4. Keys you can find (`Card.qml`, `Menu.qml`, `bin/herdr-menu-keys`)

- **The footer.** Under the list, a single elided line of the main keys,
  greyed with `faint`, at caption size:
  - the panel: `n new · a ask · i stop · x end · + − size · ? keys`;
  - the menu: the same line.
  - A field the row doesn't allow (for example `i` on a classic row) still
    shows. The line is about the keys, not the row.
- **`?`** runs `bin/herdr-menu-keys` (the sheet, `:1-15`) through a detached
  Process. In the inputs, `?` stays literal.
- **The empty state** (`Card.qml:676`) reads "No herdr sessions. Press n to
  start one."
- **One destroy key: `x`.**
  - On a running classic session it asks to kill the server.
  - On a stopped one it asks to delete it.
  - On an app agent it asks to end that agent, with the cascade, as `K` does
    today.
- **`K` stays as an alias of `x`,** so existing habits keep working. The key
  sheet lists `x`, and `K` as "same as x".
- **`herdr-menu-keys` and the README** list the new keys, and drop the
  column ones (U5).

### U5. Drop the column cursor (`HerdrModel.qml`, `Card.qml`)

- **What goes.** `column`, `columnOpen`, `lastColumnFor`, `moveColumn`,
  `cycleColumn` and `clampColumn`, with their call sites.
- **Card.** `onMoveRequested` handles only `dy`. `onTabRequested` and the
  per-button cursor highlight (`Card.qml:606`) go.
- **The buttons** stay, clickable with the mouse, and gain accessible names
  (U8).
- **`activateCursor()`** keeps its row behaviour:
  - Enter on an agent lands on it;
  - on a session, it opens it;
  - on a stopped one, it starts it.

### U6. Keep the highlighted agent on screen (`Card.qml`, `HerdrModel.qml`)

- **`HerdrModel.showRow`** passes both `sessionIndex` and `agentIndex`.
- **`Card.showRow(si, ai)`:**
  1. calls `positionViewAtIndex(si, ListView.Contain)` as now;
  2. when `ai >= 0`, maps the agent row's rectangle into `list.contentItem`
     and moves `contentY` by the least that brings it inside the view.
- Session rows keep today's behaviour.

### U7. `n`: say what it will make, and where (`Menu.qml`)

- **The behaviour is unchanged** (intent Q4): the row under the cursor
  decides the host and the kind.
- **The input label** (`Menu.qml:441`) says both:
  - "New session on p620"
  - "New session on razer"
  - "New space on p620"
  - "New space on razer"

  The host name is this machine's hostname, or the row's host.
- **The placeholder** in `newField` is "name, optionally followed by a folder
  path".
- **The prompt input** gets the placeholder "message to <agent title>".

### U8. Prompt reply, layer, motion, focus and accessibility (`Menu.qml`, `Panel.qml`, `Card.qml`)

- **The reply.**
  - `replyFrom()` is deleted. The reply shows the last 40 lines of the
    output the action returned, at most 4000 characters (cut at a line
    start), in the theme's monospace font.
  - Line breaks and indentation are kept, and the box scrolls.
- **While the prompt waits,** the input line reads "waiting 12 s · Esc
  cancels", ticking each second.
- **The layer.** `WlrLayer.Overlay` becomes `WlrLayer.Top` in
  `Panel.qml:323` (pinned card) and `Menu.qml:354` (menu).
  - The menu keeps its exclusive keyboard focus.
  - Risk R2 covers the fullscreen check.
- **The blink** (`Card.qml:487`) runs for at most 60 s per attention
  episode, then stays lit.
  - A new episode starts the 60 s again: another agent becoming the most
    urgent, or the same agent's status changing.
  - The model owns this with a `blinkUntil` time.
- **Pinning from the keyboard** (`p`) gives the pinned window's catcher
  active focus once the window maps (`Panel.qml:136-139`, `:455-469`).
- **Accessibility.**
  - Row and agent delegates set `Accessible.focused` to "this row is the
    cursor".
  - `newField` gets `Accessible.name` from the label (U7).
  - Each icon button gets a name: "Open session", "Kill server", "Delete
    session", "End agent", "Pin" or "Unpin".

### U9. One priority rule (`HerdrModel.qml`)

- **`priority(counts)`** returns `"blocked"`, `"done"`, `"working"` or
  `"idle"`, from an object with `blocked`, `done` and `working` (a session,
  or the totals).
- **`noteColor`, `statusColor` and `badgeColor`** map from it.
  `attentionRank` keeps its status-to-rank table and ranks by it.
- **`noteLabel`** uses it too.
- Behaviour is unchanged: only where the order is decided moves.

### U10. One confirm scaffold (`ConfirmOverlay.qml` new, `Card.qml`, `Menu.qml`)

- **A new `ConfirmOverlay.qml`** wraps the repeated scaffolding:
  - the input-blocking `MouseArea`;
  - the dim backdrop;
  - centring the shell's `ConfirmDialog`;
  - passing `fontFamily` and the text size.
- **Card's destroy confirm** (`:695`) and **Menu's busy-send confirm**
  (`:498`) use it, and keep their own texts and actions.
- **Imports.** `Panel.qml:2` and `:5` are removed if `omarchy plugin validate`
  and the QML load test still pass.

### U11. README

- **Corrected:**
  - the agent title styling (`README.md:203`), now plain or dimmed;
  - the polling description (`:284-286`);
  - the badge description (U1);
  - the key table (U2, U4, U5).
- **Added:** a "Text size" line.

### U12. The shared model: deferred

A follow-up issue is filed when this PR opens. It covers sharing collection
across surfaces while keeping per-surface cursor and focus state.

## Alternatives rejected

- **Badge number = running servers (today's fallback).** It means something
  different from the blocked count, and hc-only machines have no servers.
- **Text size from the theme's `base-size`.** It's global, and it's already
  possible; the owner asked for the panel itself.
- **Per-surface text sizes.** They're confusing, and a pinned card and the
  menu showing the same rows at different sizes buys nothing.
- **`Qt.lighter` on light themes and `Qt.darker` on dark.** That needs theme
  detection; alpha works on both with one rule.
- **Keeping the column cursor and adding hints.** It keeps two ways to do
  the same thing, and the buttons sit on the wrong row while an agent is
  selected.
- **Making `n` always local.** It removes the only keyboard route to a
  remote host or an app space. A clear label keeps the route without the
  surprise.
- **A Markdown or code renderer for replies.** It's heavier, and a raw
  excerpt with its whitespace intact is what the owner asked for.

## Risks

- **R1. Losing muscle memory.**
  - Dropping Left/Right, h/l and Tab changes navigation. It is documented in
    the key sheet and the README.
  - `K` stays as an alias, so the destroy key doesn't change underfoot.
- **R2. Top layer under fullscreen.** If the menu, on Top, opens under a
  fullscreen window, it may hold the keyboard while invisible.
  - The check: a throwaway fullscreen window in the `nixarchy-desktop`
    microVM.
  - If Top fails there, the menu stays on Overlay and only the pinned card
    moves to Top. That fallback is recorded as a plan deviation if used.
- **R3. Width growth.**
  - At 1.6x on a narrow monitor the card is capped by the room on screen, so
    text elides more.
  - The check: demo-mode screenshots at 0.8x, 1.0x and 1.6x, on p620's
    2560 px monitor and the microVM's 1280 px screen.
- **R4. The file watch.** Two models writing at once could race; the last
  write wins, which is harmless for one number. Reads ignore anything that
  isn't a number in range.
- **R5. A badge on idle classic servers is gone.**
  - A user who relied on "3" meaning three servers now sees no badge when
    nothing is active.
  - The tooltip and title still give the count. This is the intended change.
- **R6. Deploy.** New QML types need `omarchy-restart-shell` after the
  switch, as #22 showed. It is announced on the agent bus first.

## Verification

- **Unit tests** (`node tests/session-actions.cjs`), new cases:
  - `needCount` and the badge text for: blocked only; done only; working
    only (dot, no number); stale with and without a count; hc-only with no
    classic server; idle (hidden);
  - text steps: clamping at 0.8 and 1.6, no drift after 20 steps, reset,
    and a bad stored value giving 1.0;
  - key routing: bare `+ = - 0 ?` act outside the inputs and stay literal
    inside; the Ctrl chords act in both;
  - `x` on a running classic session, a stopped one and an app agent
    (each to the right confirm), and `K` matching `x`;
  - `priority()` for each mix, and the colours unchanged against today's
    results;
  - the reply excerpt: indentation kept, 40-line and 4000-character caps,
    cut at a line start;
  - blink: stops at 60 s and restarts on a new episode;
  - source checks:
    - no `Qt.darker` on text in the QML;
    - no `column` API left;
    - `Accessible.focused` and the named buttons are present.
- **QML load test** (`bash tests/app-subscription.sh`, extended): the model
  reads and writes the `text-scale` file in a temp `XDG_CACHE_HOME`. A
  second model instance sees the change.
- **Shell tests** (`bash tests/herdr-sessions.sh`): unchanged and green,
  plus the `herdr-menu-keys --print` text.
- **Checks:** `shellcheck` and `omarchy plugin validate .` pass.
- **CI is green before merge.**
- **Visual and live, after deploy and a shell restart:**
  - demo-mode screenshots on p620, read-only: the badge states, the footer,
    the text sizes and the empty state;
  - a light-theme check in the microVM;
  - the R2 fullscreen check in the microVM;
  - one throwaway hc agent for a live badge on hc-only rows.
