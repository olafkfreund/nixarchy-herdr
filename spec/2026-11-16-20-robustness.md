# Spec: actions never hang, the cursor stays on what you picked, failures say why

Implements the approved intent. Resolved there: a second action is refused
with a visible line and never blocks kill; prompt text stays in argv, and the
docs are corrected to say so.

Revision 2 follows the Codex review of revision 1 (gpt-6.1-sol, 2026-11-16).
The agy review was not obtained: it hit agy's 10-minute print timeout. Decision A
(D6) was taken on 2026-11-16.

Line numbers are on `2e1c3f4`.

## Design

### D0. Ground rules for the script

`bin/herdr-sessions` keeps `set -euo pipefail` (`:38`). It stops relying on it
for anything that may fail:

- **Every command that is allowed to fail is checked where it runs,** with
  `if`, `|| rc=$?` or `|| true`. Nothing depends on errexit propagating out of a
  function, because errexit is off inside any function called from a
  condition.
- **`show_session`'s window lookup (`:564`) gets `|| true`.** A missing window
  is the normal case and must not exit the script.
- **A timeout is exit 124, or 137 when `-k` had to kill.** Both mean
  "timed out" everywhere below.

### D1. Every external call has a hard deadline

- **One wrapper:**

  ```bash
  bounded() { local s=$1; shift; timeout -k 1 "$s" "$@"; }
  ```

  `ssh_run` (`:151`) uses it as well.
- **Local calls that get a limit:**

  | Call | Where | Limit |
  |---|---|---|
  | `herdr agent focus` | `:658` | 4 s |
  | `agent get`, `agent read` after a prompt | `:804-806` | 4 s |
  | `socket_of` → `herdr session list` | `:850` | 4 s |
  | `herdr session delete` | `:903` | 8 s |
  | `hyprctl clients -j`, `hyprctl dispatch` | `:237`, `:577-588` | 2 s |
  | `pgrep -af herdr` | `:262` | 2 s |

- **A timeout is reported, never swallowed.** A call that times out ends with
  `die "timed out: <what>"`. `remote_action` (`:910`) keeps the exit status of
  `ssh_run` and reports 124/137 as `timed out: <action> on <host>`, not as
  "unreachable".
- **What a prompt timeout means:**
  - The 300 s wait running out is not a failure, because the prompt was
    delivered. The result stays `ok:true` with `status:"timeout"`, and the menu
    shows "still working after 5 min" above the excerpt.
  - The `agent get` and `agent read` that follow are not allowed to time out.
    If either does, the result is `die "timed out: reading the reply"`.
- **Remote `new` with a directory:**
  - It polls until `$SECONDS` reaches 30, and starts a poll only if 8 s still
    fit before that.
  - Worst case: 8 s existence check + 30 s + 8 s `workspace create` = 46 s.

### D2. A second action is refused, and kill has its own process

- **`run()` and `newSession()` report busy instead of returning silently.**
  They set `actionError = "busy: <running action> is still running"` and return
  `false`; they return `true` when they start.
- **Kill runs in its own `Process`, `killProc`,** with its own `killPendingKey`.
  A wedged focus never blocks kill.
- **One error line, last completion wins.** Both processes write the same
  `actionError`.

### D3. One completion per run, and the surface closes only on success

- **A run completes once, after both its output and its exit status are in.**
  Every action `Process` (`actionProc`, `killProc`, `promptProc`, the host
  polls) stores its stdout in a property in `onStreamFinished` and its exit
  code in `onExited`. Whichever arrives second runs one `complete()`.
- **A `Process` is never restarted before its previous run's `onExited`.** So
  the properties belong to one run, and nothing needs a separate run id.
- **What counts as failure:** unparseable output, `ok:false`, or a non-zero exit
  code. Any of them sets `actionError`; nothing clears it except success or a
  new open.
- **Success decides whether the surface closes.**
  - `openSession` and `focusAgent` pass `dismissOnSuccess`.
  - `complete()` calls `dismiss()` only on success.
  - A pinned panel never dismisses (`:265`).
- **`n` keeps your text until it works.** `submitNew` (`Menu.qml:140`) keeps the
  line open and read-only while the action runs. On success it closes the line
  and the menu. On failure it re-enables the line, keeping your text, and the
  error shows in the existing error line (`Card.qml:209-216`). An invalid name
  sets `actionError` (`HerdrModel.qml:583`).
- **A launcher that fails at once is reported.**
  - `show_session` (`:610-626`) keeps the launcher's PID and waits 0.3 s.
  - If the launcher has already exited non-zero, it returns 2, and the caller
    reports `die "the terminal exited at once"`.
  - **Limitation:** this only catches the first process (`setsid`, then
    `uwsm-app` or the terminal) failing within 0.3 s. A wrapper that exits 0
    before the terminal fails is not caught. The README says so.
- **A failed `hyprctl dispatch`** returns 3 → `die "could not focus the window"`.
- **Focus failures are reported:** `|| true` at `:656-658` becomes
  `timed out: focus` or `herdr could not focus that pane`.

### D4. The cursor is tied to an identity, not a row number

- **`rowKey(sessions, row)`** returns
  - `agentKey(session, pane)` for an agent row,
  - `sessionKey(session) + "\u0000"` for a session row.
- **`rebuild()` (`:185`) resolves the old key before replacing anything.**
  1. Compute `oldKey` from the current `sessions` and `navRows`.
  2. Build the new rows with a plain function, `navRowsFor(all)`, the same
     logic as the `navRows` binding (`:373`), which now calls it.
  3. Find `oldKey` in those rows.
  4. Assign `sessions`, then `cursor`: the found index, or else the old index
     clamped to the new length.
  5. Call `clampColumn()`.

  Nothing depends on when the binding updates.
- **Moving the cursor yourself sets `cursorPlaced = true`:** `moveCursor`,
  `moveColumn`, `cycleColumn`, `cursorToAgent` and `cursorToSession`. The first
  poll then no longer moves the cursor to `bestRow()` (`:211`).
- **Known remaining edge:** a delegate rebuilt under a still pointer can fire
  `onContainsMouseChanged` (`Card.qml:576`) and move the cursor to the row under
  the pointer. That is the same as moving the mouse, and it predates this
  change. It is listed for the live check rather than redesigned.

### D5. The confirm dialog acts on the session as it is now

- **`confirmPending()` (`:349`) looks up the session by `sessionKey` in the
  current `sessions`.** If any of these is true, it does nothing and sets
  `actionError = "<label> changed; nothing done"`:
  - the session is gone
  - kill: the session is no longer running
  - delete: the session is running now
- **The dialogs close with the surface.** `onOpenedChanged` closes calls
  `closeConfirm()`, and `Menu.close()` clears `promptConfirmOpen`.

### D6. Kill: an exact socket, every candidate PID, and a check before each signal

- **`server_pid_for` (`:830`) takes the socket from a whole field.**
  - It reads `ss -lpxn`.
  - A line counts only if one of its whitespace-separated fields is exactly the
    socket path. That is exact equality, not `index()`, and it doesn't matter
    which column holds it.
  - From that line it walks every `pid=N` inside `users:(…)`.
- **A PID is the server only if both checks pass:**
  - `/proc/N/comm` is `herdr`.
  - The second line of `tr '\0' '\n' < /proc/N/cmdline` is exactly `server`.
    `tr` is used because bash variables cannot hold NUL.
- **The start time is recorded with the PID.**
  - It comes from `/proc/N/stat`, cut after the last `") "`, so a `comm`
    containing `") "` cannot shift the fields.
  - The start time is then the 20th field after the cut (field 22 overall).
  - `parent_pid` (`:215`) gets the same last-match cut (`##`).
- **Each signal is preceded by a check.** `cmd_kill` calls
  `same_process pid start` immediately before TERM and before KILL. If the
  process no longer matches, the server has already exited, and the result is
  `{"ok":true}`. The two wait loops become one function, `wait_gone`.

**Decided 2026-11-16: option A.** Bash cannot send a signal atomically to an
exact process, so a PID reused in the microseconds between the check and the
`kill` is out of scope. The intent was amended to match: kill checks,
immediately before each signal, that the process is still that server. The
rejected option was a python3 pidfd helper, which would add python3 to every
remote host's requirements.

### D7. Only real herdr clients count as windows

`session_in_args` (`:283`) scans the words after `herdr`:

- **Recognised:** `--session X`, `--session=X`, `--remote X`, `--remote=X`.
- **Any other word starting with `-` is skipped as a flag,** so an unknown long
  option is tolerated, as test 7 (`tests/herdr-sessions.sh:189`) expects.
- **The first word that is neither a flag nor a flag's value decides:**
  - `session` followed by `attach X`: a client of session X.
  - Anything else (`agent`, `api`, `server`, `session list`, …): not a client.
- **No such word:** a client of the default or named session, as now.
- **Accepted false negative:** an unknown flag that takes a separate value
  (`--foo bar`) makes `bar` look like a subcommand. The window is then not
  found, and open starts a new one. That is the existing safe fallback.

### D8. Snapshots in parallel, each projected separately, all under the listing's budget

- **One budget for the whole listing.** It is `LIST_BUDGET=6` s from the start
  of `cmd_list`, measured with `$SECONDS`.
  - The 4 s session list counts against it.
  - Each snapshot's limit is `min(2, remaining − 1)`, and none starts with
    less than 1.5 s left.
  - So a remote `list` finishes inside ssh's 8 s with at least 1 s for
    assembly and transfer.
- **Up to `SNAPSHOT_JOBS=4` at once.**
  - The job PIDs are kept in an array, and it waits with `wait -n || true`.
  - A failing job is expected and never ends the collector.
- **Each job projects its snapshot into the exact shape the merge consumes,**
  with one jq in the job (in parallel):
  - `agents`, `workspaces` and `tabs` are arrays of objects.
  - Each consumed field is coerced: strings with `tostring`, `seq` with
    `tonumber? // 0`.
  - If the projection fails, the job writes nothing.
- **The merge reads only projected files.** A missing file means unreadable, so
  one bad reply can no longer fail the list. The whole-object check at `:442` is
  removed: every file was already checked on its own.
- **Run directory and cleanup:**
  - `RUN_DIR` is a global set once by `mktemp -d` under `$XDG_RUNTIME_DIR`
    (else `/tmp`); `umask 077` covers the permissions.
  - One trap on `EXIT INT TERM HUP` kills any job PIDs still running, waits for
    them, then removes `RUN_DIR`.
  - Jobs only exist inside `cmd_list`, but the trap and the variables are
    global, so `set -u` cannot trip on a variable that went out of scope.
- **A running session with no projected snapshot is emitted with
  `readable: false`.** That covers a failed or oversized reply, or one that ran
  out of budget. `countLabel()` (`HerdrModel.qml:613`) shows "unreadable".
  `rebuild()` counts `unreadableCount`, and the tooltip names it.
- **Why 4 jobs:**
  - Healthy snapshots take well under 0.1 s, so 4 jobs read any realistic list
    quickly.
  - About 8 wedged servers fit in the budget; any more show as unreadable
    instead of stalling.
  - It is a constant, easy to tune.

### D9. Every counted agent has a row

- **Untitled agents are kept.** `:501` stops dropping them, and their title
  becomes `"untitled agent"`.
- **Counts are taken over the shown list.** `agents`, `blocked`, `done` and
  `working` (`:484-488`) are computed after the priority sort and the 500-agent
  cap (`:516`), not before.
  - The sort puts blocked first, then done, then working, so the badge stays
    right unless one session has more than 500 blocked agents.
  - Agents beyond the cap are reported as `hiddenAgents`, and `countLabel` adds
    "(N not shown)".

### D10. Caps bound the output; existence is checked without them

- **`session_exists` (`:671`) stops using the capped list.** It reads
  `herdr session list --json` directly: `bounded 4` locally, `ssh_run` remotely.
  That list is uncapped by name, so the cap can no longer hide a duplicate, and
  it is cheaper.
- **The session cap applies to the output.** The final jq keeps
  `.[0:$sessionCap]` after sorting and emits `hidden: N`. Card's error line shows
  "N sessions not shown" when N > 0. The unused `dropped` counter is removed.
- **The final output is size-checked locally too.** Over `TOTAL_BYTE_CAP`, it is
  `die "session list too large to show"`, as `cmd_list_remote` already does
  (`:546`).
- **Lengths count bytes.**
  - Functions that compare lengths declare `local LC_ALL=C` before any
    `${#var}`: `cmd_list` around `:401`, and `over_byte_cap`.
  - The screen is truncated with `head -c` (`:809`).
  - `jq -R` turns a UTF-8 sequence cut at the end into U+FFFD, which is the
    defined behaviour.
- **The screen reaches jq on stdin,** via `jq -Rs --arg status`, not
  `--arg output` (`:820`).

### D11. Stale data is marked

- **A host with no answer since the menu opened is "checking", not "down".**
  - `stateOfHost()` (`:222`) returns `"checking"` for it.
  - On open, `hostState` is reset to `{}`.
  - `hostSummary()` draws checking as `…`.
- **Kill and delete wait until the host has answered.** On a host that is
  checking or down they are refused with `"<host> not checked yet"`. The rows
  are still drawn.
- **Late answers from an earlier open are ignored.** `pollGen` goes up on every
  close. Each host poll delegate copies it when it starts, and by D3 it cannot
  restart before its last run ends. `complete()` ignores runs whose generation
  is older. That fixes the false "down" on a fast reopen (`:859`).
- **Ending a poll ends its local ssh.** `cmd_list_remote` runs ssh as a direct
  background child and traps TERM, as `cmd_prompt` does (`:788`). So
  `poll.running = false` ends the local ssh.
  - **The remote side is not signalled:** sshd doesn't promise to deliver a
    hang-up to the remote command (see `:765`).
  - The remote collector is bounded by its own `LIST_BUDGET` (D8) and ends by
    itself within 6 s. The README says so.
- **Hosts removed from `herdr.json` go at once.** `hostsFile.onLoaded` and
  `onLoadFailed` call a new `applyHosts(list)`. It prunes `hostSessions` and
  `hostState` to the hosts still listed, then calls `rebuild()`.
- **A failed local poll shows in the tooltip.** It keeps the rows and sets
  `reachable = false`, and `tooltipText()` shows `"Herdr: " + errorText`. The
  badge is already hidden then (`Panel.qml:231`).

### D12. Demo mode hides remote hosts

The `list` dispatch (`:932`) checks `demo_on` before `$HOST`. With `--host`
in demo mode it prints `{"ok":true,"error":"","sessions":[]}`.

### D13. Prompt handling

- **The text survives a failure.** `submitPrompt` (`Menu.qml:187`) clears
  `newField` only on success.
- **No retargeting while a prompt waits.** `beginInput` refuses while
  `promptProc.running`: "a prompt is still waiting; Esc stops waiting".
- **Cancel, then resubmit:** the field stays read-only until the cancelled
  run's `onExited`, by D3's rule. So the old result can never land on the new
  run.
- **The docs say where the text goes:** `README.md`, plus the comments at
  `Menu.qml:228` and `bin/herdr-sessions:728`. The text crosses the panel and
  ssh on stdin, but herdr takes it as an argument, so local processes can see
  it while the prompt waits.

### D14. Small display logic

- **`cleanTitle` (`:638`) strips only known leading noise:** Braille spinners
  U+2800-28FF, box drawing U+2500-257F, the glyphs `✳✻●◐◓◑◒•`, and spaces.
- **The tie-break does what its comment says.** `updateAttention` (`:751`) sets
  a `tied` flag when two new candidates share a `seq`, and then nobody blinks.
- **Polling slows down once nothing is working.** The poll interval (`:906`)
  uses `blockedCount > 0 || workingCount > 0`. The badge colour still uses
  `badgeActive`.

## Alternatives rejected

- **Queueing a second action:** a focus or delete would run after the rows had
  changed. Refused at intent.
- **A run id per `Process` start:** "no restart before `onExited`" (D3) gives
  the same guarantee with no bookkeeping.
- **A QML watchdog on `actionProc`:** D1's limits are already hard because of
  `-k`, and a second timer would race them.
- **Unbounded parallel snapshots:** up to 200 `herdr` processes every 3 s.
- **Sequential snapshots under one deadline:** wedged servers at the top use up
  the budget, and the healthy ones below them are never read.
- **Validating the snapshot type only (revision 1):** a bad `agents` field
  still failed the whole merge. That was confirmed with jq.
- **Rewriting every `fn || die` to `fn; rc=$?` (revision 1):** under `set -e`
  the script exits before `rc=$?` runs. That was confirmed in bash.
- **Removing stale remote rows on reopen:** the list would jump. Marking them
  as checking, and refusing destructive actions on them, answers the same
  risk.
- **Keeping the prompt out of argv with `agent send-keys`:** it changes how a
  prompt arrives, and loses herdr's `--wait`. Decided at intent.

## Risks

- **Each running session gets one jq in its job (D8),** where there were none
  before. They run 4 at a time inside the budget. The cost is checked in the
  live test against the old version (`time bin/herdr-sessions list`).
- **The 0.3 s launcher check** slows only opens that start a new window.
- **`wait -n` needs bash ≥ 4.3.** p620 and razer run 5.x, and the script already
  needs bash 4.
- **Snapshots briefly sit on disk.** Projected snapshots, with agent titles,
  stay in a mode-700 directory for under 6 s per refresh. The README's "nothing
  written to disk" becomes "nothing kept after a refresh".
- **Close only on success:** an unpinned dropdown now stays open for as long as
  the action runs. That is usually under 0.5 s, and at most the action's limit.
- **The remote collector outlives a closed menu by up to 6 s** (D11).
- **The Node harness tests JS functions, not QML bindings or `Process` signal
  order.** D3 and D4 are covered by functions written to be testable, and by
  the live check.
- **Hosts:** p620 is local and razer is remote. Both get the change through the
  nixarchy pin bump after merge.
