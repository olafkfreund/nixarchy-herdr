# Spec: actions never hang, the cursor stays on what you picked, failures say why

Implements the approved intent. Resolved there: a second action is refused
with a visible line and never blocks kill; prompt text stays in argv, and the
docs are corrected to say so.

## Design

Each decision names the intent problem it answers. Line numbers are on
`2e1c3f4`.

### D1. Every external call has a hard deadline (freezes)

- **One wrapper in `bin/herdr-sessions`:**

  ```bash
  bounded() { local s=$1; shift; timeout -k 1 "$s" "$@"; }
  ```

  `-k 1` turns each limit into a hard one: a child that ignores TERM is killed
  a second later. `ssh_run` uses it too (`:151`).
- **Local calls that get a limit:**

  | Call | Where | Limit |
  |---|---|---|
  | `herdr agent focus` | `:658` | 4 s |
  | `agent get`, `agent read` after a prompt | `:804-806` | 4 s |
  | `socket_of` → `herdr session list` | `:850` | 4 s |
  | `herdr session delete` | `:903` | 8 s |
  | `hyprctl clients -j`, `hyprctl dispatch` | `:237`, `:577-588` | 2 s |
  | `pgrep -af herdr` | `:262` | 2 s |

  The calls that already have one keep it: list 4 s, snapshot 2 s, prompt 300 s.
- **A limit that runs out says so.** The action prints
  `{"ok":false,"error":"timed out: <action>"}`. `die` and the JSON shape are
  unchanged.
- **Remote `new` with a directory waits on one deadline, not a loop count.**
  `:709-716` changes from 20 iterations to "until `$SECONDS` reaches 30 s". With
  the 8 s existence check and the 8 s `workspace create` around it, the whole
  action is bounded at about 46 s, down from about 186 s.

### D2. A second action is refused, and kill has its own process (freezes, refused-not-dropped)

- **`HerdrModel.qml`:** `run()` (`:250`) and `newSession()` (`:582`) set
  `actionError = "busy: <running action> is still running"` and return `false`
  instead of returning silently. They return `true` when they start.
- **Kill gets its own `Process`, `killProc`,** with the same stdout handling.
  `killSession()` uses `killProc`, so a wedged focus never blocks kill. A second
  kill while one runs gets the busy line.
- **Rejected:** a queue (see Alternatives).

### D3. Failures are reported, and the surface closes only on success (hides failures)

- **Close only on success.** `openSession`, `focusAgent` and the menu's
  `submitNew` stop dismissing straight away. `run()` takes a
  `dismissOnSuccess` flag. The `actionProc` result handler calls `dismiss()`
  only on `ok:true`.
- **An unreadable result is an error.** Unparseable output or a non-zero exit
  sets `actionError = "<action> failed"` instead of clearing it (`:879-884`).
- **`n` keeps your text.** `submitNew` (`Menu.qml:140`) keeps the input open and
  read-only while the action runs. On `ok:true` it closes the input and the
  menu. On failure it re-enables the input with your text, and the error shows
  in the existing error line (`Card.qml:209-216`).
- **An invalid name is reported.** It sets `actionError = "not a valid session
  name"` (`HerdrModel.qml:583`) instead of returning quietly.
- **Starting a terminal is checked.** `show_session` (`:618-626`) keeps the
  launcher's PID, waits 0.3 s, and if the launcher has already exited non-zero,
  returns 2. `cmd_open`, `cmd_new` and `cmd_focus` map 2 to
  `die "the terminal exited at once"`.
- **A failed `hyprctl dispatch` returns 3** → `die "could not focus the window"`.
- **No `||` after a function call.** Every `fn || die` becomes
  `fn; rc=$?` with an explicit check, so `set -e` stays on inside the function.
- **Focus failures are no longer swallowed.** `|| true` at `:656-658` becomes a
  checked call. Exit 124 → `die "timed out: focus"`; any other non-zero →
  `die "herdr could not focus that pane"`.

### D4. The cursor is tied to an identity, not a row number (acts on the wrong thing)

- **`rowKey(row)` in `HerdrModel.qml`** returns `agentKey(session, pane)` for an
  agent row, and `sessionKey(session) + "\u0000"` for a session row. Both
  already exist (`:738`, `:742`).
- **`rebuild()` (`:185`)** reads the key under the cursor before assigning
  `sessions`. Afterwards it finds that key in the new `navRows` and puts the
  cursor there. If the key is gone, the cursor keeps its index, clamped to the
  list. Then it calls `clampColumn()`.
- **Moving the cursor yourself sets `cursorPlaced = true`:** `moveCursor`,
  `moveColumn`, `cycleColumn`, `cursorToAgent` and `cursorToSession`. The first
  poll then no longer moves the cursor to `bestRow()` (`:211`).

### D5. The confirm dialog acts on the session as it is now (acts on the wrong thing)

- **`confirmPending()` (`:349`)** looks up the session by `sessionKey` in the
  current `sessions` before acting. It does nothing, and sets
  `actionError = "<label> changed; nothing done"`, when any of these is true:
  - the session is gone
  - kill: it is no longer running
  - delete: it is now running
- **The dialogs close with the surface.** `onOpenedChanged` closes calls
  `closeConfirm()`. `Menu.close()` also clears `promptConfirmOpen`.

### D6. Kill signals only that session's own server (acts on the wrong thing)

- **`server_pid_for` (`:830`) matches the socket path exactly.** It reads
  `ss -lpxn` with awk and compares the local-address field for equality
  (`$5 == socket`), instead of using `index()`.
- **It takes the right PID from the `users:(…)` list.** It walks every `pid=N`
  and keeps the first one that passes both checks:
  - `/proc/N/comm` is `herdr`
  - the second NUL-separated argument of `/proc/N/cmdline` is exactly `server`
- **It records the process start time,** field 22 of `/proc/N/stat`, and prints
  `pid starttime`.
- **`cmd_kill` re-checks before every signal.** `same_process pid starttime`
  checks that `comm` and the start time still match before TERM and before KILL.
  If they don't, the server already exited and the result is `{"ok":true}`.
- **The two wait loops become one function,** `wait_gone pid`.

### D7. Only real herdr clients count as windows (acts on the wrong thing)

`session_in_args` (`:283`) recognises the client forms from `herdr --help`:

- **Accepted as a client:**
  - bare `herdr` with only `--session X`, `--session=X`, `--remote X` and
    `--remote=X`
  - `herdr session attach X`
- **Not a client:** a first word that doesn't start with `-` and isn't a flag's
  value (`agent`, `api`, `server`, `session list` and so on), so `return 1`.
- **`-s` is not handled,** because `herdr --help` doesn't list it.

### D8. Snapshots in parallel, each validated separately, under one deadline (freezes, hides failures)

- **Up to 4 at a time.** `cmd_list` starts snapshot jobs in the background, at
  most `SNAPSHOT_JOBS=4` at once, using `wait -n`. Each job writes to a file in
  a run directory created with `mktemp -d` under `$XDG_RUNTIME_DIR` (else
  `/tmp`), mode 700 through `private_dir`, and removed by a trap on exit.
- **Each snapshot is validated on its own** with
  `jq -e '.result.snapshot | type == "object"'`, and only valid ones are
  spliced in. The whole-object fallback at `:442` stays as a last resort, but
  can no longer be reached by a single bad reply.
- **One deadline for the whole collection: 5 s,** measured with `$SECONDS` from
  when collecting starts, so it stays under the ssh 8 s limit with room for the
  rest. Once it passes, no more jobs start, and running jobs are left to their
  own 2 s limit.
- **Unread servers are named.** A running session with no valid snapshot (it
  failed, was over the cap, or was not started before the deadline) is emitted
  with `readable: false`. `countLabel()` (`HerdrModel.qml:613`) then shows
  "unreadable" instead of "no agents". `rebuild()` counts these into a new
  `unreadableCount`, which the tooltip mentions.
- **Why 4 jobs:** healthy snapshots take well under 0.1 s, so 4 jobs read any
  realistic list of healthy servers well inside the deadline. Wedged servers
  cost 2 s each, so 4 jobs fit about 10 of them in 5 s; any beyond that show as
  unreadable instead of stalling the refresh. More jobs would mean more `herdr`
  processes every 3 s for little gain. It is a constant, so it is easy to
  tune.

### D9. Every counted agent has a row (hides failures)

`:501` stops dropping agents with an empty title. An empty or whitespace title
becomes `"untitled agent"`. `cleanTitle` already handles the rest.

### D10. The caps bound the output, in bytes (hides failures)

- **The session cap applies to the output.** The final jq keeps
  `.[0:$sessionCap]` after sorting and emits `hidden: N`, the number cut. Card's
  error line shows "N sessions not shown" when N > 0. That is a status text,
  not a new UI element.
- **The unused `dropped` counter is removed.**
- **Lengths count bytes.** `${#snapshots}` and the like run under
  `LC_ALL=C` (`:401`). The screen is truncated with `head -c` instead of
  `${screen:0:N}` (`:809`).
- **The screen goes to jq on stdin,** `jq -Rs` with `--arg status` only, not
  `--arg output` (`:820`).

### D11. Stale data is marked (hides failures)

- **Hosts start as checking.** `stateOfHost()` (`:222`) returns `"checking"`
  for a host with no answer since the menu opened, not `"down"`. On open,
  `hostState` is reset to `{}`. `hostSummary()` draws checking as `…`.
- **No destructive action on unchecked data.** A host in checking or down
  refuses kill and delete with `actionError = "<host> not checked yet"`. Rows
  are still drawn, so the list doesn't jump.
- **A late answer from an old poll is ignored.** A `pollGen` counter increases
  on every close. Each host poll records the generation it started in, and
  `applyHostPayload` ignores answers and exits from an older one. That fixes
  the false "down" on a quick reopen (`:859`).
- **Closing the menu ends the ssh as well.** `cmd_list_remote` runs ssh as a
  direct background child with a TERM trap, the way `cmd_prompt` already does
  (`:788`). That way `poll.running = false` reaches ssh too.
- **Removed hosts go at once.** `hostsFile.onLoaded` and `onLoadFailed` keep
  only the hosts still listed in `hostSessions` and `hostState`, then call
  `rebuild()`.
- **A failed local poll is visible.** `applyPayload` with `ok:false` keeps the
  rows, sets `reachable = false`, and `tooltipText()` returns
  `"Herdr: " + errorText` while unreachable. The badge is already hidden then
  (`Panel.qml:231`).

### D12. Demo mode hides remote hosts (smaller)

The `list` dispatch (`:932`) checks `demo_on` before `$HOST`. With `--host` in
demo mode, it prints `{"ok":true,"error":"","sessions":[]}`.

### D13. Prompt handling (smaller, hides failures)

- **The text survives a failure.** `submitPrompt` (`Menu.qml:187`) stops clearing
  `newField` before the result. It clears it on `ok:true`, and keeps it with the
  error otherwise.
- **No retargeting while a prompt waits.** `beginInput` refuses while
  `promptProc.running`, and says "a prompt is still waiting; Esc stops waiting".
- **Late results are dropped.** A `promptGen` counter, increased on every
  cancel and submit, makes the result handler ignore output from an earlier
  run.
- **Where the text goes, stated correctly.** `README.md`, the comments at
  `Menu.qml:228` and `bin/herdr-sessions:728`: the text crosses the panel and
  ssh on stdin, but herdr takes it as an argument, so local processes can see
  it while the prompt waits.

### D14. Small display logic (smaller)

- **`cleanTitle` (`:638`) strips only known leading noise:** Braille spinners
  U+2800-28FF, box drawing U+2500-257F, and the status glyphs `✳✻●◐◓◑◒•`, plus
  spaces. Every script survives.
- **The tie-break does what its comment says.** `updateAttention` (`:751`)
  tracks a `tied` flag: an equal `seq` among new candidates means nobody blinks.
- **Polling slows down** when only done agents are left. The interval
  (`:906`) uses `blockedCount > 0 || workingCount > 0`, not `badgeActive`. The
  badge colour still uses `badgeActive`.

## Alternatives rejected

- **Queueing a second action:** a focus or delete would run after the rows
  changed. Refused at intent.
- **One process per action type:** only kill must never be blocked. Three or
  more processes would add bookkeeping for nothing.
- **A QML watchdog timer on `actionProc`:** the script-level limits (D1) are
  hard limits with `-k`. A second timer would race them.
- **Unbounded parallel snapshots:** up to 200 `herdr` processes every 3 s.
- **Sequential snapshots under one deadline:** wedged servers at the top use up
  the budget, and healthy ones below are never read.
- **Removing the stale remote rows on reopen:** the list would jump. Marking
  them checking and refusing destructive actions answers the same risk.
- **Keeping prompt text out of argv** with an expect-style paste through
  `agent send-keys`: it changes how prompts arrive, and herdr's own
  `agent prompt` with `--wait` is the supported route. Decided at intent.
- **pidfd or `kill --timeout`:** not available from bash in a form that works
  on every remote host. A start-time check does the same job portably.

## Risks

- **The 0.3 s launcher check** adds 0.3 s to every open that has to start a
  window. Opens that focus an existing window are unchanged.
- **The `ss` field layout:** `$5` is the local address on iproute2 ≥ 5. Older
  iproute2 on a remote host could put it elsewhere. Mitigation: the awk matches
  any field equal to the socket path, not `$5` only.
- **`wait -n` needs bash ≥ 4.3.** razer and p620 run 5.x. The script already
  needs bash 4 for `declare -A`.
- **Temp files on remote hosts:** the run directory lives under the remote
  `$XDG_RUNTIME_DIR` or `/tmp`, mode 700, and is removed on exit. Snapshots
  are written there for less than 5 s. They hold session titles, which the old
  version only kept in memory. The README's "nothing written to disk" sentence
  is corrected to "nothing kept after a refresh".
- **Dismissing on success** means an unpinned dropdown stays open for the
  length of the action (usually under 0.5 s; up to the action's limit when
  something is wrong).
- **Hosts:** p620 is local, razer is remote. Both get it through the nixarchy
  pin bump after merge, not from this branch.

## Verification

  gain `FAKE_FOCUS_SLEEP`, `FAKE_BAD_SNAPSHOT` and an `ss` fake:
  - a wedged focus ends in about 4 s with `timed out: focus` (D1)
  - one bad snapshot among three: the other two keep their agents, and the bad
    one is `readable:false` (D8)
  - three slow snapshots finish in about 2 s in parallel, not about 6 s (D8)
  - an agent with an empty title is listed as "untitled agent" (D9)
  - over the session cap gives `hidden > 0` and a capped list (D10)
  - demo mode with `--host` gives an empty list (D12)
  - `herdr agent prompt …` and `herdr session list` in the process list are not
    windows; `--session=foo` is (D7)

    another, signals only the herdr server (D6)
  - a terminal launcher that exits at once gives `the terminal exited at once`
